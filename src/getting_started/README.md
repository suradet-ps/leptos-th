# เริ่มต้นใช้งาน

คุณสามารถเริ่มต้นพัฒนาด้วย Leptos ได้ 2 แนวทางหลักตามเป้าหมายของโปรเจกต์:

1. **การเรนเดอร์ฝั่งไคลเอนต์ (Client-Side Rendering: CSR) ด้วย [Trunk](https://trunk-rs.github.io/trunk/)** — เป็นตัวเลือกที่ยอดเยี่ยมหากคุณต้องการสร้างเว็บไซต์หรือเว็บแอปพลิเคชันที่ตอบสนองรวดเร็วฉับไว หรือต้องการเชื่อมต่อกับเซิร์ฟเวอร์และ API ที่มีอยู่เดิม
   ในโหมด CSR นั้น Trunk จะคอมไพล์โค้ด Leptos ของคุณเป็น WebAssembly (WASM) แล้วรันบนเบราว์เซอร์ของผู้ใช้โดยตรง เช่นเดียวกับ Single-Page Application (SPA) ทั่วไปที่เขียนด้วย JavaScript ข้อดีของ Leptos CSR คือความเร็วในการบิลด์ วงจรการพัฒนาที่สั้นและคล่องตัว แบบจำลองทางความคิด (mental model) ที่เข้าใจง่าย ตลอดจนทางเลือกในการนำแอปไปดีพลอยที่ยืดหยุ่นหลากหลาย อย่างไรก็ดี แอปแบบ CSR ก็มีข้อแลกเปลี่ยนที่ต้องพิจารณา ได้แก่ เวลาโหลดเริ่มต้น (initial load time) ของผู้ใช้จะช้ากว่าแนวทางฝั่งเซิร์ฟเวอร์ และมีความท้าทายด้าน SEO เช่นเดียวกับ SPA ทั่วไป นอกจากนี้ การทำงานเบื้องหลังยังจำเป็นต้องพึ่งพาสคริปต์ JavaScript ตัวเล็กๆ ที่สร้างขึ้นอัตโนมัติเพื่อทำหน้าที่โหลดบันเดิล WASM ดังนั้นเบราว์เซอร์ของผู้ใช้จึง**จำเป็นต้องเปิดใช้งาน JavaScript** เพื่อให้แอปแสดงผลได้อย่างถูกต้อง เช่นเดียวกับงานวิศวกรรมซอฟต์แวร์ทุกประเภท คุณจะต้องชั่งน้ำหนักข้อดีข้อเสียเหล่านี้ให้เหมาะกับงานของคุณ

2. **ฟูลสแตกเรนเดอร์ฝั่งเซิร์ฟเวอร์ (Full-Stack SSR) ด้วย [`cargo-leptos`](https://github.com/leptos-rs/cargo-leptos)** — SSR เหมาะอย่างยิ่งสำหรับการสร้างเว็บแอปแบบ CRUD และเว็บแอปพลิเคชันที่ต้องการใช้ Rust ขับเคลื่อนทั้งส่วนหน้าบ้าน (Frontend) และหลังบ้าน (Backend)
   เมื่อเลือกใช้ SSR ตัวแอปพลิเคชันจะเรนเดอร์หน้าตาเป็น HTML ส่งตรงจากเซิร์ฟเวอร์ไปยังเบราว์เซอร์ของผู้ใช้ทันที จากนั้นจึงนำ WebAssembly เข้าไปผูกเข้ากับ HTML เพื่อเปิดให้ผู้ใช้สามารถโต้ตอบกับหน้าเว็บได้ กระบวนการนี้เรียกว่า "การไฮเดรต (Hydration)" ทางฝั่งเซิร์ฟเวอร์ Leptos SSR สามารถผสานการทำงานร่วมกับเว็บเฟรมเวิร์กยอดนิยมของ Rust ได้อย่างแนบแน่น ไม่ว่าจะเป็น [Actix-web](https://docs.rs/leptos_actix/latest/leptos_actix/) หรือ [Axum](https://docs.rs/leptos_axum/latest/leptos_axum/) ทำให้คุณสามารถดึงพลังของระบบนิเวศและไลบรารีของชุมชนเหล่านั้นมาใช้งานได้อย่างเต็มที่
   ข้อดีของการใช้ SSR คือคุณจะได้เวลาโหลดหน้าแรกที่เร็วที่สุดและคะแนน SEO ที่ยอดเยี่ยม นอกจากนี้ แอป SSR ยังช่วยลดความยุ่งยากในการเชื่อมต่อระหว่างไคลเอนต์กับเซิร์ฟเวอร์ลงอย่างมาก ด้วยฟีเจอร์เด่นของ Leptos ที่เรียกว่า "ฟังก์ชันฝั่งเซิร์ฟเวอร์ (Server Functions)" ซึ่งเปิดให้คุณเรียกฟังก์ชันบนเซิร์ฟเวอร์จากโค้ดฝั่งไคลเอนต์ได้อย่างไร้รอยต่อ แต่แน่นอนว่า SSR ก็ไม่ได้มีแต่ข้อดีไปทั้งหมด ข้อจำกัดที่ต้องแลกมาคือรอบการพัฒนาที่อาจใช้เวลาคอมไพล์นานขึ้น (เพราะต้องคอมไพล์โค้ด Rust ใหม่ทั้งฝั่งเซิร์ฟเวอร์และไคลเอนต์) รวมถึงความซับซ้อนบางประการที่มาพร้อมกับกระบวนการไฮเดรต

เมื่ออ่านหนังสือเล่มนี้จบ คุณจะเห็นภาพชัดเจนว่าข้อแลกเปลี่ยนในแต่ละจุดคืออะไร และควรเลือกแนวทางใด — CSR หรือ SSR — ให้ตอบโจทย์ความต้องการของโปรเจกต์คุณมากที่สุด

ใน**ส่วนที่ 1** ของหนังสือ เราจะเริ่มต้นด้วยการสร้าง UI แบบรีแอกทีฟในโหมดการเรนเดอร์ฝั่งไคลเอนต์ (CSR) โดยใช้เครื่องมือ `Trunk` เพื่อเสิร์ฟบันเดิล JS และ WASM ไปยังเบราว์เซอร์

จากนั้นใน**ส่วนที่ 2** เราจะแนะนำการใช้งาน `cargo-leptos` เพื่อปลดล็อกพลังเต็มรูปแบบของ Leptos ในโหมดฟูลสแตกและการเรนเดอร์ฝั่งเซิร์ฟเวอร์ (SSR)

```admonish note
หากคุณมีพื้นฐานมาจากฝั่ง JavaScript และคำอย่าง Client-Side Rendering (CSR) หรือ Server-Side Rendering (SSR) ยังฟังดูไม่คุ้นเคย เราสามารถเปรียบเทียบง่ายๆ ได้ดังนี้:

- **โหมด CSR ของ Leptos**: เทียบได้กับการใช้ React (หรือเฟรมเวิร์กที่ขับเคลื่อนด้วย Signal อย่าง SolidJS) ซึ่งเน้นการสร้าง UI ฝั่งไคลเอนต์เป็นหลัก โดยคุณสามารถนำไปต่อเข้ากับเทคโนโลยีหลังบ้านภาษาใดก็ได้
- **โหมด SSR ของ Leptos**: เทียบได้กับเฟรมเวิร์กฟูลสแตกอย่าง Next.js ในโลกของ React (หรือ SolidStart ของ Solid) ซึ่งช่วยให้คุณสร้างเว็บที่เรนเดอร์มาจากเซิร์ฟเวอร์ แล้วส่งผลลัพธ์ลงมาแสดงผลที่เบราว์เซอร์ SSR ช่วยเพิ่มความเร็วในการโหลดเนื้อหา ปรับปรุงความสามารถในการเข้าถึง (Accessibility) และช่วยให้นักพัฒนาคนเดียวสามารถดูแลโค้ดทั้งฝั่งไคลเอนต์และเซิร์ฟเวอร์ได้สะดวก โดยไม่ต้องสลับบริบทไปมาระหว่างภาษาที่ต่างกัน

คุณจึงเลือกได้ว่าจะใช้ Leptos พัฒนาเฉพาะหน้าบ้านในโหมด CSR (สไตล์ React) หรือจะใช้ในโหมดฟูลสแตก SSR (สไตล์ Next.js) เพื่อสร้างทั้งระบบด้วยภาษา Rust เพียงภาษาเดียว
```

## Hello World! เตรียมพร้อมสำหรับการพัฒนา Leptos CSR

ขั้นตอนแรก ตรวจสอบให้แน่ใจว่าคุณได้ติดตั้ง Rust และอัปเดตเป็นเวอร์ชันล่าสุดแล้ว ([อ่านคำแนะนำการติดตั้งได้ที่นี่](https://www.rust-lang.org/tools/install))

หากยังไม่ได้ติดตั้ง คุณสามารถติดตั้งเครื่องมือ "Trunk" สำหรับบิลด์และรันเว็บแอป Leptos CSR ผ่านบรรทัดคำสั่งได้ดังนี้:

```bash
cargo install --locked trunk
```

จากนั้น สร้างโปรเจกต์ Rust เริ่มต้น:

```bash
cargo init leptos-tutorial
```

ใช้คำสั่ง `cd` เข้าไปยังไดเรกทอรีโปรเจกต์ `leptos-tutorial` แล้วเพิ่ม `leptos` เข้าเป็นดีเพนเดนซี:

```bash
cargo add leptos --features=csr
```

เพิ่ม target `wasm32-unknown-unknown` เข้ามา เพื่อให้ Rust สามารถคอมไพล์โค้ดของคุณเป็น WebAssembly สำหรับรันบนเบราว์เซอร์ได้:

```bash
rustup target add wasm32-unknown-unknown
```

สร้างไฟล์ `index.html` ไว้ที่รากของไดเรกทอรีโปรเจกต์ `leptos-tutorial`:

```html
<!DOCTYPE html>
<html>
  <head></head>
  <body></body>
</html>
```

และเพิ่มโค้ด “Hello, world!” สั้นๆ ลงใน `main.rs`:

```rust
use leptos::prelude::*;

fn main() {
    leptos::mount::mount_to_body(|| view! { <p>"Hello, world!"</p> })
}
```

โครงสร้างไดเรกทอรีของคุณควรมีลักษณะดังนี้:

```
leptos_tutorial
├── src
│   └── main.rs
├── Cargo.toml
├── index.html
```

ตอนนี้ ให้รันคำสั่ง `trunk serve --open` จากรากของโปรเจกต์ `leptos-tutorial`
Trunk จะคอมไพล์แอปพลิเคชันของคุณโดยอัตโนมัติ และเปิดหน้าเว็บขึ้นมาในเบราว์เซอร์เริ่มต้น
หากคุณแก้ไขโค้ดใน `main.rs` ทาง Trunk จะตรวจพบและคอมไพล์ใหม่ พร้อมทำ Live-Reload หน้าเว็บให้อัตโนมัติทันที

ยินดีต้อนรับสู่โลกแห่งการพัฒนา UI ด้วย Rust และ WebAssembly (WASM) ที่ขับเคลื่อนโดย Leptos และ Trunk!

```admonish note
หากคุณใช้งาน Windows คำสั่ง `trunk serve --open` อาจไม่สามารถเปิดเบราว์เซอร์ให้อัตโนมัติได้ หากพบปัญหาดังกล่าว คุณสามารถใช้คำสั่ง `trunk serve` ธรรมดา แล้วเปิดหน้าต่างเบราว์เซอร์ไปยัง URL ที่ระบุด้วยตนเอง
```

---

ก่อนที่เราจะไปลงมือสร้างแอปพลิเคชันจริง มีเกร็ดและเครื่องมือที่เป็นประโยชน์อีกสองสามอย่างที่คุณควรรู้ เพื่อให้การใช้งาน Leptos ราบรื่นและสะดวกสบายยิ่งขึ้น
