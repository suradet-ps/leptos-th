# เริ่มต้นใช้งาน

มีเส้นทางพื้นฐานสองเส้นทางในการเริ่มต้นใช้งาน Leptos:

1. **การเรนเดอร์ฝั่งไคลเอนต์ (CSR) ด้วย [Trunk](https://trunk-rs.github.io/trunk/)** - เป็นตัวเลือกที่ยอดเยี่ยมหากคุณเพียงต้องการสร้างเว็บไซต์ที่ตอบสนองฉับไวด้วย Leptos หรือทำงานร่วมกับเซิร์ฟเวอร์หรือ API ที่มีอยู่แล้ว
   ในโหมด CSR นั้น Trunk จะคอมไพล์แอป Leptos ของคุณเป็น WebAssembly (WASM) แล้วรันในเบราว์เซอร์เหมือนกับเว็บแอปแบบ single-page (SPA) ทั่วไปที่เขียนด้วย JavaScript ข้อดีของ Leptos CSR ได้แก่ เวลาบิลด์ที่เร็วขึ้น วงจรการพัฒนาแบบวนซ้ำที่รวดเร็วขึ้น ตลอดจนแบบจำลองทางความคิดที่เรียบง่ายกว่าและตัวเลือกในการดีพลอยแอปที่มากกว่า อย่างไรก็ตาม แอป CSR ก็มีข้อเสียอยู่บ้าง: เวลาโหลดเริ่มต้นสำหรับผู้ใช้ปลายทางช้ากว่าเมื่อเทียบกับแนวทางการเรนเดอร์ฝั่งเซิร์ฟเวอร์ และความท้าทายด้าน SEO ที่มักมาพร้อมกับโมเดลเว็บแอปแบบ single-page ที่ใช้ JS ก็ใช้กับแอป Leptos CSR เช่นกัน นอกจากนี้ ภายใต้ฮู้ดยังมีการใช้โค้ด JS ที่สร้างขึ้นอัตโนมัติเพื่อโหลดบันเดิล WASM ของ Leptos ดังนั้นจึง**จำเป็น**ต้องเปิดใช้งาน JS บนอุปกรณ์ของผู้ใช้เพื่อให้แอป CSR แสดงผลได้อย่างถูกต้อง เช่นเดียวกับงานวิศวกรรมซอฟต์แวร์ทุกแขนง คุณจะต้องพิจารณาข้อแลกเปลี่ยนเหล่านี้ด้วย

2. **ฟูลสแตกที่เรนเดอร์ฝั่งเซิร์ฟเวอร์ (SSR) ด้วย [`cargo-leptos`](https://github.com/leptos-rs/cargo-leptos)** - SSR เหมาะอย่างยิ่งสำหรับการสร้างเว็บไซต์แบบ CRUD และเว็บแอปที่กำหนดเอง หากคุณต้องการให้ Rust ขับเคลื่อนทั้งฟรอนต์เอนด์และแบ็กเอนด์
   ด้วยตัวเลือก Leptos SSR แอปของคุณจะถูกเรนเดอร์เป็น HTML บนเซิร์ฟเวอร์แล้วส่งลงมาให้เบราว์เซอร์ จากนั้นจึงใช้ WebAssembly เพื่อติดตั้งการทำงานให้กับ HTML ให้แอปของคุณโต้ตอบได้ ซึ่งกระบวนการนี้เรียกว่า 'การไฮเดรต (hydration)' ทางฝั่งเซิร์ฟเวอร์ แอป Leptos SSR จะผสานรวมอย่างใกล้ชิดกับไลบรารีเซิร์ฟเวอร์ที่คุณเลือก ไม่ว่าจะเป็น [Actix-web](https://docs.rs/leptos_actix/latest/leptos_actix/) หรือ [Axum](https://docs.rs/leptos_axum/latest/leptos_axum/) คุณจึงสามารถใช้ประโยชน์จากครีตของชุมชนเหล่านั้นมาช่วยสร้างเซิร์ฟเวอร์ Leptos ของคุณได้
   ข้อดีของการเลือกใช้ SSR กับ Leptos ได้แก่ ช่วยให้ได้เวลาโหลดเริ่มต้นที่ดีที่สุดและคะแนน SEO ที่เหมาะสมที่สุดสำหรับเว็บแอปของคุณ แอป SSR ยังช่วยลดความซับซ้อนในการทำงานข้ามขอบเขตเซิร์ฟเวอร์/ไคลเอนต์ได้อย่างมากผ่านฟีเจอร์ของ Leptos ที่เรียกว่า "ฟังก์ชันฝั่งเซิร์ฟเวอร์ (server functions)" ซึ่งช่วยให้คุณเรียกฟังก์ชันบนเซิร์ฟเวอร์จากโค้ดฝั่งไคลเอนต์ได้อย่างโปร่งใส (รายละเอียดของฟีเจอร์นี้จะกล่าวถึงในบทต่อๆ ไป) อย่างไรก็ตาม ฟูลสแตกแบบ SSR ไม่ได้สวยงามไปเสียทั้งหมด ข้อเสียได้แก่วงจรการพัฒนาสำหรับนักพัฒนาที่ช้าลง (เพราะต้องคอมไพล์ทั้งเซิร์ฟเวอร์และไคลเอนต์ใหม่เมื่อแก้ไขโค้ด Rust) รวมถึงความซับซ้อนที่เพิ่มขึ้นซึ่งมาพร้อมกับการไฮเดรต

เมื่ออ่านหนังสือเล่มนี้จบ คุณน่าจะเข้าใจได้ดีว่าควรแลกเปลี่ยนสิ่งใดและควรเลือกเส้นทางไหน - CSR หรือ SSR - ตามความต้องการของโปรเจกต์ของคุณ

ในส่วนที่ 1 ของหนังสือเล่มนี้ เราจะเริ่มต้นจากเว็บไซต์ Leptos แบบการเรนเดอร์ฝั่งไคลเอนต์ และการสร้าง UI แบบรีแอกทีฟโดยใช้ `Trunk` เพื่อเสิร์ฟบันเดิล JS และ WASM ให้กับเบราว์เซอร์

เราจะแนะนำ `cargo-leptos` ในส่วนที่ 2 ของหนังสือ ซึ่งเป็นส่วนที่ว่าด้วยการใช้งานพลังเต็มรูปแบบของ Leptos ในโหมดฟูลสแตกและ SSR

```admonish note
หากคุณมาจากโลกของ JavaScript และคำอย่างการเรนเดอร์ฝั่งไคลเอนต์ (CSR) กับการเรนเดอร์ฝั่งเซิร์ฟเวอร์ (SSR) ยังไม่คุ้นหู วิธีที่ง่ายที่สุดในการทำความเข้าใจความแตกต่างคือการเปรียบเทียบ:

โหมด CSR ของ Leptos คล้ายกับการทำงานกับ React (หรือเฟรมเวิร์กที่ใช้ 'สัญญาณ' อย่าง SolidJS) และเน้นการสร้าง UI ฝั่งไคลเอนต์ที่คุณสามารถใช้ร่วมกับเทคโนโลยีฝั่งเซิร์ฟเวอร์ใดก็ได้

การใช้โหมด SSR ของ Leptos คล้ายกับการทำงานกับเฟรมเวิร์กแบบฟูลสแตกอย่าง Next.js ในโลกของ React (หรือเฟรมเวิร์ก "SolidStart" ของ Solid) - SSR ช่วยให้คุณสร้างเว็บไซต์และแอปที่เรนเดอร์บนเซิร์ฟเวอร์แล้วส่งลงมาให้ไคลเอนต์ SSR ช่วยปรับปรุงประสิทธิภาพการโหลดและการเข้าถึงของเว็บไซต์ ตลอดจนทำให้คนคนเดียวทำงานทั้งฝั่งไคลเอนต์ *และ* ฝั่งเซิร์ฟเวอร์ได้ง่ายขึ้น โดยไม่ต้องสลับบริบทไปมาระหว่างภาษาที่ต่างกันสำหรับฟรอนต์เอนด์และแบ็กเอนด์

เฟรมเวิร์ก Leptos ใช้ได้ทั้งในโหมด CSR เพื่อสร้าง UI เพียงอย่างเดียว (เหมือน React) หรือจะใช้ Leptos ในโหมดฟูลสแตก SSR (เหมือน Next.js) เพื่อสร้างทั้ง UI และเซิร์ฟเวอร์ด้วยภาษาเดียวคือ Rust

```

## Hello World! เตรียมพร้อมสำหรับการพัฒนา Leptos CSR

อย่างแรก ตรวจสอบให้แน่ใจว่าได้ติดตั้ง Rust และอัปเดตให้เป็นเวอร์ชันล่าสุดแล้ว ([ดูวิธีติดตั้งได้ที่นี่](https://www.rust-lang.org/tools/install))

หากคุณยังไม่ได้ติดตั้ง คุณสามารถติดตั้งเครื่องมือ "Trunk" สำหรับรันเว็บไซต์ Leptos CSR ได้โดยรันคำสั่งต่อไปนี้บนบรรทัดคำสั่ง:

```bash
cargo install --locked trunk
```

จากนั้นสร้างโปรเจกต์ Rust พื้นฐาน

```bash
cargo init leptos-tutorial
```

`cd` เข้าไปในโปรเจกต์ `leptos-tutorial` ใหม่ของคุณ แล้วเพิ่ม `leptos` เป็นดีเพนเดนซี

```bash
cargo add leptos --features=csr
```

ตรวจสอบให้แน่ใจว่าคุณได้เพิ่ม target `wasm32-unknown-unknown` แล้ว เพื่อให้ Rust คอมไพล์โค้ดของคุณเป็น WebAssembly สำหรับรันในเบราว์เซอร์ได้

```bash
rustup target add wasm32-unknown-unknown
```

สร้างไฟล์ `index.html` ง่ายๆ ไว้ที่รากของไดเรกทอรี `leptos-tutorial`

```html
<!DOCTYPE html>
<html>
  <head></head>
  <body></body>
</html>
```

และเพิ่ม “Hello, world!” ง่ายๆ ลงใน `main.rs` ของคุณ

```rust
use leptos::prelude::*;

fn main() {
    leptos::mount::mount_to_body(|| view! { <p>"Hello, world!"</p> })
}
```

โครงสร้างไดเรกทอรีของคุณตอนนี้ควรมีหน้าตาประมาณนี้

```
leptos_tutorial
├── src
│   └── main.rs
├── Cargo.toml
├── index.html
```

ตอนนี้ให้รัน `trunk serve --open` จากรากของไดเรกทอรี `leptos-tutorial`
Trunk ควรคอมไพล์แอปของคุณโดยอัตโนมัติและเปิดมันในเบราว์เซอร์เริ่มต้นของคุณ
หากคุณแก้ไข `main.rs` Trunk จะคอมไพล์ซอร์สโค้ดของคุณใหม่และ
รีโหลดหน้าเพจแบบสดๆ

ยินดีต้อนรับสู่โลกของการพัฒนา UI ด้วย Rust และ WebAssembly (WASM) ที่ขับเคลื่อนโดย Leptos และ Trunk!

```admonish note
หากคุณใช้ Windows โปรดทราบว่า `trunk serve --open` อาจไม่ทำงาน หากคุณพบปัญหากับ `--open`
เพียงใช้ `trunk serve` แล้วเปิดแท็บเบราว์เซอร์ด้วยตนเอง
```
