# ส่วนที่ 2: การเรนเดอร์ฝั่งเซิร์ฟเวอร์

ดังที่คุณได้อ่านไปในบทที่แล้ว การพัฒนาเว็บแอปพลิเคชันแบบเรนเดอร์ฝั่งไคลเอนต์นั้นยังมีข้อจำกัดอยู่บางประการ ในส่วนที่สองของหนังสือเล่มนี้ เราจะมาพูดคุยกันถึงวิธีใช้การเรนเดอร์ฝั่งเซิร์ฟเวอร์ (SSR) เพื่อก้าวข้ามข้อจำกัดเหล่านี้ และดึงประสิทธิภาพสูงสุดรวมถึงผลลัพธ์ด้าน SEO ที่ดีที่สุดออกมาจากแอปพลิเคชัน Leptos ของคุณ


```admonish info

เมื่อพัฒนา Leptos บนฝั่งเซิร์ฟเวอร์ คุณมีอิสระเต็มที่ในการเลือกใช้เฟรมเวิร์กเซิร์ฟเวอร์ ไม่ว่าจะเป็นตัวที่รองรับอย่างเป็นทางการ เช่น Actix หรือ Axum หรือจะเลือกใช้ตัวเลือกที่พัฒนาและดูแลโดยชุมชน ฟีเจอร์ครบครันทั้งหมดของ Leptos จะใช้งานได้เต็มรูปแบบกับตัวเลือกที่เป็นทางการ ส่วนตัวเลือกของชุมชนอาจรองรับฟีเจอร์ได้น้อยกว่า โปรดตรวจสอบเอกสารของแต่ละตัวเลือกสำหรับรายละเอียดเพิ่มเติม

เรามีตัวเลือกหลากหลายที่ชุมชนให้การสนับสนุน รวมถึงรันไทม์ที่สอดคล้องกับมาตรฐาน WinterCG เช่น Deno หรือ Cloudflare และรันไทม์ WASM ฝั่งเซิร์ฟเวอร์ เช่น Spin นอกจากนี้ การผสานการทำงานกับ Viz และ Pavex ที่ชุมชนดูแลก็เป็นอีกทางเลือกหนึ่งสำหรับเซิร์ฟเวอร์แบบดั้งเดิม การเขียนตัวเชื่อมต่อ (integration) ขึ้นมาใช้เองนั้นไม่แนะนำสำหรับผู้เริ่มต้น แต่ผู้ใช้ภาษา Rust ระดับกลางหรือระดับสูงอาจสนใจที่จะทดลองทำ และสามารถเข้ามาสอบถามเกี่ยวกับเรื่องนี้ได้ตลอดเวลาบน Discord หรือ GitHub ของเรา

สำหรับผู้เริ่มต้น ขอแนะนำให้เลือกใช้ Axum หรือ Actix ซึ่งทั้งสองตัวทำงานได้อย่างสมบูรณ์แบบ และการเลือกระหว่างสองตัวนี้ขึ้นอยู่กับความชอบส่วนบุคคลเป็นหลัก ไม่มีตัวเลือกใดผิด แต่หากคุณต้องการคำแนะนำ ทีมงานของ Leptos ในปัจจุบันใช้ Axum เป็นค่าเริ่มต้นสำหรับโปรเจกต์ใหม่
```
