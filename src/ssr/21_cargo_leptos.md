# ทำความรู้จักกับ `cargo-leptos`

จนถึงตอนนี้ เราเพิ่งรันโค้ดในเบราว์เซอร์และใช้ Trunk ในการประสานกระบวนการบิลด์และรันกระบวนการพัฒนาภายในเครื่องเท่านั้น หากเราจะเพิ่มการเรนเดอร์ฝั่งเซิร์ฟเวอร์ เราก็จำเป็นต้องรันโค้ดแอปพลิเคชันของเราบนเซิร์ฟเวอร์ด้วย ซึ่งหมายความว่าเราต้องบิลด์ไบนารีสองตัวแยกจากกัน ตัวหนึ่งคอมไพล์เป็นโค้ดเนทีฟและรันบนเซิร์ฟเวอร์ ส่วนอีกตัวคอมไพล์เป็น WebAssembly (WASM) และรันในเบราว์เซอร์ของผู้ใช้ นอกจากนี้ เซิร์ฟเวอร์ยังต้องรู้วิธีเสิร์ฟ WASM เวอร์ชันนี้ (รวมถึง JavaScript ที่จำเป็นในการเริ่มต้นมัน) ให้กับเบราว์เซอร์ด้วย

นี่ไม่ใช่ภารกิจที่เกินความสามารถ แต่มันเพิ่มความซับซ้อนขึ้นบ้าง เพื่อความสะดวกและประสบการณ์การพัฒนาที่ง่ายขึ้น เราได้สร้างเครื่องมือบิลด์ [`cargo-leptos`](https://github.com/leptos-rs/cargo-leptos) ขึ้นมา โดยพื้นฐานแล้ว `cargo-leptos` มีไว้เพื่อประสานกระบวนการบิลด์สำหรับแอปของคุณ จัดการการคอมไพล์ครึ่งเซิร์ฟเวอร์และครึ่งไคลเอนต์ใหม่เมื่อคุณแก้ไขโค้ด และเพิ่มการรองรับในตัวสำหรับสิ่งต่างๆ อย่าง Tailwind, SASS และการทดสอบ

เริ่มต้นได้ค่อนข้างง่าย เพียงรัน

```bash
cargo install --locked cargo-leptos
```

จากนั้นในการสร้างโปรเจกต์ใหม่ คุณสามารถรันได้ทั้ง

```bash
# for an Actix template
cargo leptos new --git https://github.com/leptos-rs/start-actix
```

หรือ

```bash
# for an Axum template
cargo leptos new --git https://github.com/leptos-rs/start-axum
```

ตรวจสอบให้แน่ใจว่าคุณได้เพิ่ม target wasm32-unknown-unknown แล้ว เพื่อให้ Rust คอมไพล์โค้ดของคุณเป็น WebAssembly สำหรับรันในเบราว์เซอร์ได้
```bash
rustup target add wasm32-unknown-unknown
```

ตอนนี้ `cd` ไปยังไดเรกทอรีที่คุณสร้างขึ้นแล้วรัน

```bash
cargo leptos watch
```

เมื่อแอปของคุณคอมไพล์เสร็จแล้ว คุณสามารถเปิดเบราว์เซอร์ไปที่ [`http://localhost:3000`](http://localhost:3000) เพื่อดูได้เลย

`cargo-leptos` มีฟีเจอร์เพิ่มเติมและเครื่องมือในตัวมากมาย อ่านเพิ่มเติมได้[ใน `README` ของมัน](https://github.com/leptos-rs/cargo-leptos/blob/main/README.md)

แต่เกิดอะไรขึ้นกันแน่เมื่อคุณเปิดเบราว์เซอร์ไปที่ `localhost:3000`? อ่านต่อเพื่อหาคำตอบ
