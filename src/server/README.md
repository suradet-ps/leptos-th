# การทำงานกับเซิร์ฟเวอร์

ในหัวข้อก่อนหน้านี้ เราได้อธิบายถึงกระบวนการเรนเดอร์ฝั่งเซิร์ฟเวอร์ (Server-Side Rendering) โดยใช้เซิร์ฟเวอร์เพื่อสร้างหน้าเพจเวอร์ชัน HTML ซึ่งจะถูกอัปเกรดให้สามารถโต้ตอบได้ (interactive) เมื่อโหลดขึ้นมาบนเบราว์เซอร์ จนถึงตอนนี้ ทุกสิ่งทุกอย่างยังคงเป็นแบบ “ไอโซมอร์ฟิก” (isomorphic) หรือพูดง่าย ๆ คือ แอปของคุณมี “รูปร่างโครงสร้าง (_morphe_) ที่เหมือนกันทุกประการ (_iso_)” ไม่ว่าจะรันอยู่บนฝั่งไคลเอนต์หรือฝั่งเซิร์ฟเวอร์

แต่ในความเป็นจริง เซิร์ฟเวอร์ทำอะไรได้มากกว่าแค่การเรนเดอร์โค้ด HTML มากมายนัก! ที่จริงแล้ว เซิร์ฟเวอร์สามารถทำสิ่งต่าง ๆ สารพัดอย่างที่เบราว์เซอร์ของคุณ*ไม่มีทางทำได้* เช่น การอ่านและเขียนข้อมูลลงฐานข้อมูล SQL โดยตรง

หากคุณคุ้นเคยกับการพัฒนาแอปฟรอนต์เอนด์ด้วย JavaScript คุณอาจคุ้นชินกับการส่งคำขอไปยัง REST API เพื่อจัดการงานฝั่งเซิร์ฟเวอร์เหล่านี้ หรือหากคุณคุ้นเคยกับการพัฒนาเว็บด้วย PHP, Python, Ruby (หรือ Java, C# เป็นต้น) งานฝั่งเซิร์ฟเวอร์ย่อมเป็นงานหลักในชีวิตประจำวันของคุณอยู่แล้ว ในขณะที่ความสามารถในการโต้ตอบบนฝั่งไคลเอนต์มักกลายเป็นเรื่องที่ค่อยมาคิดทีหลัง

ด้วย Leptos คุณสามารถทำได้ทั้งสองสิ่งพร้อมกัน: ไม่เพียงแค่เขียนด้วยภาษาเดียวกัน ไม่เพียงแค่แชร์ชนิดข้อมูล (types) เดียวกัน แต่คุณยังสามารถเขียนพวกมันรวมอยู่ในไฟล์เดียวกันได้อย่างกลมกลืน!

ในหัวข้อนี้ เราจะมาเรียนรู้วิธีสร้างส่วนการทำงานที่เป็นของฝั่งเซิร์ฟเวอร์โดยเฉพาะให้กับแอปพลิเคชันของคุณ
