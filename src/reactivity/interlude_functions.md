# คั่นรายการ: รีแอกทิวิตีและฟังก์ชัน

หนึ่งในผู้ร่วมพัฒนาหลักของเราพูดกับผมเมื่อไม่นานนี้ว่า: “ผมไม่เคยใช้โคลเชอร์บ่อยขนาดนี้
เลย จนกระทั่งผมเริ่มใช้ Leptos” และมันก็จริง โคลเชอร์เป็นหัวใจของแอปพลิเคชัน Leptos
ทุกตัว บางครั้งมันก็ดูตลกนิดหน่อย:

```rust
// a signal holds a value, and can be updated
let (count, set_count) = signal(0);

// a derived signal is a function that accesses other signals
let double_count = move || count.get() * 2;
let count_is_odd = move || count.get() & 1 == 1;
let text = move || if count_is_odd() {
    "odd"
} else {
    "even"
};

// an effect automatically tracks the signals it depends on
// and reruns when they change
Effect::new(move |_| {
    logging::log!("text = {}", text());
});

view! {
    <p>{move || text().to_uppercase()}</p>
}
```

โคลเชอร์ โคลเชอร์เต็มไปหมด!

## ฟังก์ชันและเฟรมเวิร์ก UI

ฟังก์ชันเป็นหัวใจของเฟรมเวิร์ก UI ทุกตัว และเรื่องนี้ก็สมเหตุสมผลอย่างยิ่ง การสร้างส่วนติดต่อผู้ใช้โดยพื้นฐานแล้วแบ่งออกเป็นสองระยะ:

1. การเรนเดอร์ครั้งแรก
2. การอัปเดต

ในเว็บเฟรมเวิร์ก เฟรมเวิร์กจะทำการเรนเดอร์ครั้งแรกแบบใดแบบหนึ่ง จากนั้นส่งคืนการควบคุมกลับไปให้เบราว์เซอร์ เมื่อเหตุการณ์บางอย่างเกิดขึ้น (เช่น การคลิกเมาส์) หรืองานแบบอะซิงโครนัสเสร็จสิ้น (เช่น คำขอ HTTP ทำงานเสร็จ) เบราว์เซอร์จะปลุกเฟรมเวิร์กขึ้นมาเพื่ออัปเดตบางสิ่ง เฟรมเวิร์กจะรันโค้ดบางอย่างเพื่ออัปเดตส่วนติดต่อผู้ใช้ของคุณ แล้วหลับกลับไปจนกว่าเบราว์เซอร์จะปลุกมันอีกครั้ง

วลีสำคัญตรงนี้คือ “รันโค้ดบางอย่าง” วิธีที่เป็นธรรมชาติที่สุดในการ “รันโค้ดบางอย่าง” ณ จุดเวลาใดๆ ก็ตาม ไม่ว่าใน Rust หรือภาษาโปรแกรมอื่นใด คือการเรียกฟังก์ชัน และที่จริงแล้วเฟรมเวิร์ก UI ทุกตัวล้วนอาศัยการรันฟังก์ชันบางอย่างซ้ำแล้วซ้ำเล่า:

1. เฟรมเวิร์กแบบเวอร์ชวล DOM (VDOM) อย่าง React, Yew หรือ Dioxus จะรันคอมโพเนนต์หรือฟังก์ชันเรนเดอร์ซ้ำแล้วซ้ำเล่า เพื่อสร้างต้นไม้เวอร์ชวล DOM ที่สามารถกระทบยอดกับผลลัพธ์ก่อนหน้าเพื่อแพตช์ DOM
2. เฟรมเวิร์กแบบคอมไพล์อย่าง Angular และ Svelte แบ่งเทมเพลตคอมโพเนนต์ของคุณออกเป็นฟังก์ชัน “create” และ “update” โดยรันฟังก์ชัน update ซ้ำเมื่อตรวจพบการเปลี่ยนแปลงของสถานะคอมโพเนนต์
3. ในเฟรมเวิร์กแบบรีแอกทีฟละเอียดอย่าง SolidJS, Sycamore หรือ Leptos _คุณ_ เป็นผู้กำหนดฟังก์ชันที่จะถูกรันซ้ำ

นั่นคือสิ่งที่คอมโพเนนต์ทั้งหมดของเรากำลังทำอยู่

ลองดูตัวอย่าง `<SimpleCounter/>` ทั่วไปของเราในรูปแบบที่เรียบง่ายที่สุด:

```rust
#[component]
pub fn SimpleCounter() -> impl IntoView {
    let (value, set_value) = signal(0);

    let increment = move |_| *set_value.write() += 1;

    view! {
        <button on:click=increment>
            {value}
        </button>
    }
}
```

ฟังก์ชัน `SimpleCounter` เองรันเพียงครั้งเดียว สัญญาณ `value` ถูกสร้างขึ้นครั้งเดียว เฟรมเวิร์กส่งฟังก์ชัน `increment` ต่อให้เบราว์เซอร์ในฐานะตัวรับฟังเหตุการณ์ เมื่อคุณคลิกปุ่ม เบราว์เซอร์จะเรียก `increment` ซึ่งอัปเดต `value` ผ่าน `set_value` และการอัปเดตนั้นก็อัปเดตโหนดข้อความเดียวที่แสดงในวิวของเราด้วย `{value}`

ฟังก์ชันเป็นกุญแจสำคัญของรีแอกทิวิตี พวกมันมอบความสามารถให้เฟรมเวิร์กรันหน่วยที่เล็กที่สุดเท่าที่เป็นไปได้ของแอปพลิเคชันของคุณซ้ำ เพื่อตอบสนองต่อการเปลี่ยนแปลง

ดังนั้นจำไว้สองเรื่อง:

1. ฟังก์ชันคอมโพเนนต์ของคุณเป็นฟังก์ชันตั้งต้น ไม่ใช่ฟังก์ชันเรนเดอร์: มันรันเพียงครั้งเดียว
2. ค่าต่างๆ ในเทมเพลตวิวของคุณจะรีแอกทีฟได้ พวกมันต้องเป็นฟังก์ชันรีแอกทีฟ: ไม่ว่าจะเป็นสัญญาณหรือโคลเชอร์ที่ดักจับค่าและอ่านค่าจากสัญญาณ

```admonish note
ที่จริงแล้ว นี่คือความแตกต่างหลักระหว่างเวอร์ชัน stable และ nightly ของ Leptos อย่างที่คุณอาจทราบ การใช้คอมไพเลอร์ nightly และฟีเชอร์ `nightly` ช่วยให้คุณเรียกสัญญาณโดยตรงในฐานะฟังก์ชันได้ นั่นคือ `value()` แทนที่จะเป็น `value.get()`

แต่นี่ไม่ใช่แค่น้ำตาลไวยากรณ์เท่านั้น มันยังเปิดทางให้โมเดลเชิงความหมายที่สอดคล้องกันอย่างยิ่ง: สิ่งที่เป็นรีแอกทีฟคือฟังก์ชัน สัญญาณถูกเข้าถึงโดยการเรียกฟังก์ชัน การจะบอกว่า “ขอสัญญาณเป็นอาร์กิวเมนต์” คุณสามารถรับอะไรก็ได้ที่ `impl Fn() -> T` และอินเทอร์เฟซที่อิงฟังก์ชันนี้ไม่แยกความแตกต่างระหว่างสัญญาณ เมโม และสัญญาณอนุพัทธ์เลย เพราะทุกตัวสามารถเข้าถึงได้โดยการเรียกเป็นฟังก์ชัน

น่าเสียดายที่การอิมพลีเมนต์แทรต `Fn` บนสตรักต์ใดๆ อย่างสัญญาณนั้นต้องใช้ nightly Rust แม้ว่าฟีเจอร์นี้จะถูกปล่อยทิ้งไว้เฉยๆ และไม่น่าจะเปลี่ยนแปลง (หรือกลายเป็นเสถียร) ในเร็วๆ นี้ หลายคนเลี่ยง nightly ด้วยเหตุผลใดเหตุผลหนึ่ง เมื่อเวลาผ่านไป เราจึงปรับค่าเริ่มต้นสำหรับสิ่งต่างๆ เช่น เอกสาร ให้เป็น stable มากขึ้น น่าเสียดายที่เรื่องนี้ทำให้โมเดลความคิดง่ายๆ ที่ว่า “สัญญาณคือฟังก์ชัน” ตรงไปตรงมาน้อยลงสักหน่อย
```
