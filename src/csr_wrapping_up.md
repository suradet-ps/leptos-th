# การเรนเดอร์ฝั่งไคลเอนต์: บทสรุป

จนถึงตอนนี้ ทุกสิ่งทุกอย่างที่เราเขียนขึ้นมาล้วนถูกสั่งเรนเดอร์บนเบราว์เซอร์เกือบทั้งหมด เมื่อเราสร้างแอปพลิเคชันโดยใช้ Trunk ตัวแอปจะถูกส่งมอบผ่านเซิร์ฟเวอร์สำหรับการพัฒนาในเครื่อง (local development server) และเมื่อคุณบิลด์เพื่อนำไปใช้งานจริง (production) แล้วนำไปปรับใช้ (deploy) มันก็จะถูกเสิร์ฟผ่านเว็บเซิร์ฟเวอร์หรือเครือข่าย CDN ที่คุณเลือกใช้ ไม่ว่าจะในกรณีใด สิ่งที่เซิร์ฟเวอร์ส่งกลับมาให้ผู้ใช้ก็คือหน้า HTML ที่ประกอบด้วย:

1. URL ของไฟล์ไบนารีแอป Leptos ของคุณ ซึ่งถูกคอมไพล์เป็น WebAssembly (WASM)
2. URL ของไฟล์ JavaScript ที่ใช้สำหรับเตรียมสภาพแวดล้อมและเริ่มต้นการทำงานของ WASM
3. เอลิเมนต์ `<body>` ที่ว่างเปล่าสนิท

เมื่อไฟล์ JS และ WASM ถูกดาวน์โหลดจนเสร็จสิ้น Leptos จึงจะเริ่มต้นกระบวนการเรนเดอร์โครงสร้างแอปพลิเคชันของคุณลงไปใน `<body>` ซึ่งหมายความว่าจะไม่มีเนื้อหาใด ๆ ปรากฏขึ้นบนหน้าจอให้ผู้ใช้เห็นเลย จนกว่าทั้ง JS และ WASM จะโหลดและเริ่มทำงานจนเสร็จ ซึ่งแนวทางนี้มีข้อเสียสำคัญบางประการ:

1. มันเพิ่มเวลาในการโหลด เพราะหน้าจอของผู้ใช้จะว่างเปล่าจนกว่าทรัพยากรเพิ่มเติมจะถูกดาวน์โหลดเสร็จ
2. มันไม่ดีต่อ SEO เพราะเวลาโหลดนานขึ้นและ HTML ที่คุณเสิร์ฟก็ไม่มีเนื้อหาที่มีความหมาย
3. มันใช้งานไม่ได้สำหรับผู้ใช้ที่ JS/WASM โหลดไม่สำเร็จด้วยเหตุผลบางอย่าง (เช่น พวกเขาอยู่บนรถไฟและเพิ่งเข้าไปในอุโมงค์ก่อนที่ WASM จะโหลดเสร็จ; พวกเขาใช้อุปกรณ์เก่าที่ไม่รองรับ WASM; พวกเขาปิด JavaScript หรือ WASM ไว้ด้วยเหตุผลบางอย่าง; ฯลฯ)

ข้อเสียเหล่านี้อาจเกิดขึ้นได้ทั่วทั้งระบบนิเวศเว็บ แต่รุนแรงเป็นพิเศษกับแอป WASM

อย่างไรก็ตาม ขึ้นอยู่กับความต้องการของโปรเจกต์ของคุณ คุณอาจยอมรับข้อจำกัดเหล่านี้ได้

หากคุณแค่อยากดีพลอยเว็บไซต์ที่เรนเดอร์ฝั่งไคลเอนต์ของคุณ ให้ข้ามไปที่บทว่าด้วย [“การดีพลอย”](https://leptos-rs.github.io/leptos/deployment/index.html) - ที่นั่นคุณจะพบคำแนะนำเกี่ยวกับวิธีดีพลอยไซต์ Leptos CSR ของคุณได้ดีที่สุด

แต่ถ้าคุณอยากตอบกลับมากกว่าแค่แท็ก `<body>` เปล่าๆ ในหน้า `index.html` ของคุณล่ะ? ใช้ “การเรนเดอร์ฝั่งเซิร์ฟเวอร์” สิ!

หนังสือทั้งเล่มสามารถเขียน (และน่าจะเคยเขียนมาแล้ว) เกี่ยวกับหัวข้อนี้ได้ แต่โดยแก่นแท้ของมันแล้ว มันง่ายมาก: แทนที่จะตอบกลับแท็ก `<body>` เปล่าๆ ด้วย SSR คุณจะตอบกลับหน้า HTML เริ่มต้นที่สะท้อนสถานะเริ่มต้นจริงๆ ของแอปหรือไซต์ของคุณ เพื่อที่ว่าในระหว่างที่ JS/WASM กำลังโหลด และจนกว่าพวกมันจะโหลดเสร็จ ผู้ใช้จะสามารถเข้าถึงเวอร์ชัน HTML ธรรมดาได้

ส่วนที่ 2 ของหนังสือเล่มนี้ ว่าด้วย Leptos SSR จะครอบคลุมหัวข้อนี้อย่างละเอียดพอสมควร!
