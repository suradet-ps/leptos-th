# เมทาดาทา

จนถึงตอนนี้ ทุกอย่างที่เราเรนเดอร์ล้วนอยู่ภายใน `<body>` ของเอกสาร HTML และนั่นก็สมเหตุสมผล ท้ายที่สุดแล้ว ทุกสิ่งที่คุณเห็นบนหน้าเว็บก็อยู่ภายใน `<body>` ทั้งนั้น

อย่างไรก็ตาม มีหลายโอกาสที่คุณอาจต้องการอัปเดตบางอย่างภายใน `<head>` ของเอกสาร โดยใช้พรีมิทีฟรีแอกทีฟและรูปแบบคอมโพเนนต์แบบเดียวกับที่คุณใช้กับ UI

นั่นคือจุดที่แพ็กเกจ [`leptos_meta`](https://docs.rs/leptos_meta/latest/leptos_meta/) เข้ามามีบทบาท

## คอมโพเนนต์เมทาดาทา

`leptos_meta` มีคอมโพเนนต์พิเศษที่ให้คุณแทรกข้อมูลจากภายในคอมโพเนนต์ที่ใดก็ได้ในแอปพลิเคชันของคุณเข้าไปใน `<head>`:

[`<Title/>`](https://docs.rs/leptos_meta/latest/leptos_meta/fn.Title.html) ให้คุณกำหนดชื่อเรื่องของเอกสารจากคอมโพเนนต์ใดก็ได้ มันยังรับฟังก์ชัน `formatter` ที่ใช้จัดรูปแบบเดียวกันกับชื่อเรื่องที่หน้าอื่นๆ ตั้งไว้ได้ด้วย ตัวอย่างเช่น หากคุณใส่ `<Title formatter=|text| format!("{text} — My Awesome Site")/>` ในคอมโพเนนต์ `<App/>` ของคุณ แล้วใส่ `<Title text="Page 1"/>` และ `<Title text="Page 2"/>` บนเส้นทางของคุณ คุณจะได้ `Page 1 — My Awesome Site` และ `Page 2 — My Awesome Site`

[`<Link/>`](https://docs.rs/leptos_meta/latest/leptos_meta/fn.Link.html) แทรกเอลิเมนต์ `<link>` เข้าไปใน `<head>`

[`<Stylesheet/>`](https://docs.rs/leptos_meta/latest/leptos_meta/fn.Stylesheet.html) สร้าง `<link rel="stylesheet">` ด้วย `href` ที่คุณกำหนด

[`<Style/>`](https://docs.rs/leptos_meta/latest/leptos_meta/fn.Style.html) สร้าง `<style>` พร้อมกับ children ที่คุณส่งเข้ามา (ปกติเป็นสตริง) คุณใช้สิ่งนี้เพื่อนำเข้า CSS แบบกำหนดเองจากไฟล์อื่นตอนคอมไพล์ได้ `<Style>{include_str!("my_route.css")}</Style>`

[`<Meta/>`](https://docs.rs/leptos_meta/latest/leptos_meta/fn.Meta.html) ให้คุณกำหนดแท็ก `<meta>` พร้อมคำอธิบายและเมทาดาทาอื่นๆ

```admonish warning
หมายเหตุ: คอมโพเนนต์เหล่านี้ควรใช้ใน body ของแอปพลิเคชันของคุณ ในคอมโพเนนต์สักแห่ง ไม่ควรใช้ใน `<head>` (ตัวอย่างเช่น หากคุณกำลังใช้การเรนเดอร์ฝั่งเซิร์ฟเวอร์) แทนที่จะใส่คอมโพเนนต์ `leptos_meta` ลงใน `<head>` คุณสามารถและควรใช้เอลิเมนต์ HTML ที่สอดคล้องกันแทน
```

## `<Script/>` และ `<script>`

`leptos_meta` ยังมีคอมโพเนนต์ [`<Script/>`](https://docs.rs/leptos_meta/latest/leptos_meta/fn.Script.html) ด้วย และตรงนี้ก็ควรหยุดคิดสักครู่ คอมโพเนนต์อื่นๆ ทั้งหมดที่เราพิจารณามาแทรกเอลิเมนต์ที่ใช้ได้เฉพาะใน `<head>` ไว้ใน `<head>` แต่ `<script>` นั้นสามารถใส่ไว้ใน body ได้เช่นกัน

มีวิธีง่ายๆ ในการตัดสินใจว่าคุณควรใช้คอมโพเนนต์ `<Script/>` ตัว S พิมพ์ใหญ่ หรือเอลิเมนต์ `<script>` ตัว s พิมพ์เล็ก: คอมโพเนนต์ `<Script/>` จะถูกเรนเดอร์ใน `<head>` ส่วนเอลิเมนต์ `<script>` จะถูกเรนเดอร์ที่ตำแหน่งใดก็ตามที่คุณวางไว้ใน `<body>` ของส่วนติดต่อผู้ใช้ เคียงข้างเอลิเมนต์ HTML ปกติอื่นๆ สิ่งเหล่านี้ทำให้ JavaScript โหลดและทำงานในเวลาที่ต่างกัน ดังนั้นจงเลือกใช้แบบที่เหมาะกับความต้องการของคุณ

## `<Body/>` และ `<Html/>`

ยังมีเอลิเมนต์อีกสองสามตัวที่ออกแบบมาให้ HTML เชิงความหมายและการจัดสไตล์ทำได้ง่ายขึ้น `<Body/>` และ `<Html/>` ถูกออกแบบมาให้คุณเพิ่มแอตทริบิวต์ใดๆ ก็ได้ลงในแท็ก `<html>` และ `<body>` ของหน้าเพจคุณ คุณสามารถเพิ่มแอตทริบิวต์กี่ตัวก็ได้โดยใช้ไวยากรณ์ Leptos ปกติหลังตัวดำเนินการกระจาย (`{..}`) แล้วพวกมันจะถูกเพิ่มเข้าไปในเอลิเมนต์ที่เหมาะสมโดยตรง

```rust
<Html
    {..}
    lang="he"
    dir="rtl"
    data-theme="dark"
/>
```

## เมทาดาทาและการเรนเดอร์ฝั่งเซิร์ฟเวอร์

ทีนี้ บางส่วนของเรื่องนี้มีประโยชน์ในทุกสถานการณ์ แต่บางส่วนก็สำคัญเป็นพิเศษสำหรับการปรับแต่งให้ติดอันดับเสิร์ชเอนจิน (SEO) การทำให้แน่ใจว่าคุณมี `<title>` และ `<meta>` ที่เหมาะสมนั้นสำคัญมาก ครอว์เลอร์ของเสิร์ชเอนจินสมัยใหม่จัดการการเรนเดอร์ฝั่งไคลเอนต์ได้จริง กล่าวคือ แอปที่ถูกส่งเป็น `index.html` เปล่าๆ แล้วเรนเดอร์ทั้งหมดใน JS/WASM แต่มันชอบรับหน้าเพจที่แอปของคุณถูกเรนเดอร์เป็น HTML จริงๆ โดยมีเมทาดาทาอยู่ใน `<head>` มากกว่า

นี่คือสิ่งที่ `leptos_meta` มีไว้เพื่อทำเลย และในความเป็นจริง ระหว่างการเรนเดอร์ฝั่งเซิร์ฟเวอร์ มันก็ทำแบบนี้เป๊ะๆ: รวบรวมเนื้อหา `<head>` ทั้งหมดที่คุณประกาศไว้โดยใช้คอมโพเนนต์ของมันทั่วแอปพลิเคชัน แล้วแทรกมันเข้าไปใน `<head>` จริงๆ

แต่ผมกำลังพูดล่วงหน้าไปก่อนแล้ว เรายังไม่ได้พูดถึงการเรนเดอร์ฝั่งเซิร์ฟเวอร์เลยด้วยซ้ำ บทถัดไปจะพูดถึงการผสานรวมกับไลบรารี JavaScript จากนั้นเราจะสรุปการพูดคุยเรื่องฝั่งไคลเอนต์ แล้วก้าวต่อไปสู่การเรนเดอร์ฝั่งเซิร์ฟเวอร์
