# เมทาดาทา

จนถึงตอนนี้ ทุกสิ่งทุกอย่างที่เราเรนเดอร์ล้วนอาศัยอยู่ภายในแท็ก `<body>` ของเอกสาร HTML ทั้งสิ้น ซึ่งก็เป็นเรื่องที่สมเหตุสมผล เพราะท้ายที่สุดแล้ว ทุกองค์ประกอบที่คุณมองเห็นบนหน้าเว็บต่างก็ต้องอยู่ภายใน `<body>` ทั้งนั้น

อย่างไรก็ตาม ในการพัฒนาจริง มีหลายโอกาสที่คุณอาจต้องการอัปเดตข้อมูลบางอย่างที่อยู่ภายใน `<head>` ของเอกสาร โดยยังคงอยากใช้พรีมิตีฟรีแอกทีฟและรูปแบบคอมโพเนนต์แบบเดียวกับที่คุณใช้สร้าง UI

นั่นคือจุดที่แพ็กเกจ [`leptos_meta`](https://docs.rs/leptos_meta/latest/leptos_meta/) ก้าวเข้ามาตอบโจทย์

## คอมโพเนนต์เมทาดาทา

`leptos_meta` ได้เตรียมคอมโพเนนต์พิเศษที่ช่วยให้คุณสามารถแทรกข้อมูลจากภายในคอมโพเนนต์ใดก็ได้ในแอปพลิเคชันของคุณ ส่งตรงเข้าไปยังส่วน `<head>` ได้อย่างง่ายดาย:

[`<Title/>`](https://docs.rs/leptos_meta/latest/leptos_meta/fn.Title.html) ให้คุณสามารถกำหนดชื่อเรื่อง (title) ของเอกสารได้จากทุกคอมโพเนนต์ นอกจากนี้ยังรองรับฟังก์ชัน `formatter` เพื่อจัดรูปแบบของชื่อเรื่องให้เป็นไปในทิศทางเดียวกันในทุก ๆ หน้า ตัวอย่างเช่น หากคุณใส่ `<Title formatter=|text| format!("{text} — My Awesome Site")/>` ไว้ในคอมโพเนนต์ `<App/>` แล้วใส่ `<Title text="Page 1"/>` และ `<Title text="Page 2"/>` บนเส้นทางต่าง ๆ คุณก็จะได้ผลลัพธ์เป็น `Page 1 — My Awesome Site` และ `Page 2 — My Awesome Site` โดยอัตโนมัติ

[`<Link/>`](https://docs.rs/leptos_meta/latest/leptos_meta/fn.Link.html) ใช้แทรกเอลิเมนต์ `<link>` เข้าไปในส่วน `<head>`

[`<Stylesheet/>`](https://docs.rs/leptos_meta/latest/leptos_meta/fn.Stylesheet.html) สร้างแท็ก `<link rel="stylesheet">` พร้อมระบุแอตทริบิวต์ `href` ตามที่คุณกำหนด

[`<Style/>`](https://docs.rs/leptos_meta/latest/leptos_meta/fn.Style.html) สร้างแท็ก `<style>` พร้อมบรรจุโหนดลูกที่คุณส่งเข้ามา (โดยทั่วไปมักเป็นสตริง) คุณสามารถใช้สิ่งนี้เพื่ออิมพอร์ตโค้ด CSS แบบกำหนดเองจากไฟล์ภายนอกตั้งแต่ตอนคอมไพล์ได้ เช่น `<Style>{include_str!("my_route.css")}</Style>`

[`<Meta/>`](https://docs.rs/leptos_meta/latest/leptos_meta/fn.Meta.html) ช่วยให้คุณกำหนดแท็ก `<meta>` สำหรับใส่คำอธิบาย (descriptions) และข้อมูลเมทาดาทาอื่น ๆ ได้อย่างอิสระ

```admonish warning
ข้อควรระวัง: คอมโพเนนต์เหล่านี้ถูกออกแบบมาให้เรียกใช้ภายในเนื้อหา (body) ของแอปพลิเคชันของคุณ ภายใต้คอมโพเนนต์ใดคอมโพเนนต์หนึ่ง ไม่ควรนำไปวางไว้ในส่วน `<head>` โดยตรง (เช่น ในกรณีที่คุณใช้งานการเรนเดอร์ฝั่งเซิร์ฟเวอร์) แทนที่จะนำคอมโพเนนต์จาก `leptos_meta` ไปใส่ใน `<head>` คุณสามารถและควรเลือกใช้เอลิเมนต์ HTML ดั้งเดิมที่สอดคล้องกันแทน
```

## `<Script/>` และ `<script>`

`leptos_meta` ยังเตรียมคอมโพเนนต์ [`<Script/>`](https://docs.rs/leptos_meta/latest/leptos_meta/fn.Script.html) ไว้ให้ด้วย ซึ่งประเด็นนี้ควรค่าแก่การหยุดพิจารณาสักนิด: คอมโพเนนต์อื่น ๆ ทั้งหมดที่เรากล่าวถึงก่อนหน้านี้ล้วนทำหน้าที่แทรกเอลิเมนต์เฉพาะสำหรับส่วน `<head>` ลงไปใน `<head>` แต่ในความเป็นจริง แท็ก `<script>` นั้นสามารถปรากฏอยู่ในส่วนของ body ได้เช่นกัน

มีหลักการสังเกตง่าย ๆ ในการเลือกว่าเมื่อใดควรใช้คอมโพเนนต์ `<Script/>` (ตัว S พิมพ์ใหญ่) หรือเมื่อใดควรใช้เอลิเมนต์ `<script>` (ตัว s พิมพ์เล็ก): นั่นคือ คอมโพเนนต์ `<Script/>` จะถูกนำไปเรนเดอร์ไว้ในส่วน `<head>` เสมอ ส่วนเอลิเมนต์ `<script>` จะถูกเรนเดอร์ลงในส่วน `<body>` ตามตำแหน่งที่คุณวางไว้ในโครงสร้างอินเทอร์เฟซ เคียงข้างกับเอลิเมนต์ HTML ทั่วไป ซึ่งทั้งสองแบบจะทำให้ JavaScript โหลดและเริ่มทำงานในช่วงเวลาที่แตกต่างกัน ดังนั้นจึงควรเลือกใช้ให้เหมาะสมกับความต้องการของคุณ

## `<Body/>` และ `<Html/>`

นอกจากนี้ยังมีเอลิเมนต์อีกสองสามตัวที่ได้รับการออกแบบมาเพื่อช่วยให้การจัดการ HTML เชิงความหมาย (semantic HTML) และการจัดสไตล์ทำได้สะดวกยิ่งขึ้น นั่นคือ `<Body/>` และ `<Html/>` ซึ่งเปิดโอกาสให้คุณสามารถเพิ่มแอตทริบิวต์ใด ๆ ก็ได้ลงบนแท็ก `<html>` และ `<body>` ของหน้าเว็บ โดยคุณสามารถใส่แอตทริบิวต์ได้ไม่จำกัดจำนวนตามไวยากรณ์มาตรฐานของ Leptos หลังตัวดำเนินการกระจาย (`{..}`) และค่าเหล่านั้นจะถูกผูกเข้ากับเอลิเมนต์ดังกล่าวโดยตรง:

```rust
<Html
    {..}
    lang="he"
    dir="rtl"
    data-theme="dark"
/>
```

## เมทาดาทาและการเรนเดอร์ฝั่งเซิร์ฟเวอร์

แม้ว่าคุณสมบัติเหล่านี้จะมีประโยชน์ในทุก ๆ รูปแบบการพัฒนา แต่พวกมันมีความสำคัญเป็นพิเศษอย่างยิ่งต่อการปรับแต่งเว็บไซต์ให้ติดอันดับบนเครื่องมือค้นหา (SEO) การตรวจสอบให้แน่ใจว่าหน้าเว็บของคุณมีแท็ก `<title>` และ `<meta>` ที่ถูกต้องและครบถ้วนถือเป็นหัวใจสำคัญ บ็อตหรือครอว์เลอร์ (crawlers) ของเสิร์ชเอนจินสมัยใหม่สามารถประมวลผลการเรนเดอร์ฝั่งไคลเอนต์ได้ก็จริง (กล่าวคือ แอปที่ส่งมาเพียงไฟล์ `index.html` เปล่า ๆ แล้วไปเรนเดอร์ทุกอย่างด้วย JS/WASM บนเบราว์เซอร์) แต่พวกมันยังคงชอบและจัดอันดับได้ดีกว่ามากหากได้รับหน้าเว็บที่เรนเดอร์โครงสร้าง HTML ตัวจริงออกมาเรียบร้อยแล้ว พร้อมด้วยข้อมูลเมทาดาทาที่สมบูรณ์ในส่วน `<head>`

และนี่คือหน้าที่หลักของ `leptos_meta`: ซึ่งในระหว่างขั้นตอนการเรนเดอร์ฝั่งเซิร์ฟเวอร์ (SSR) มันจะทำหน้าที่รวบรวมเนื้อหาทั้งหมดของ `<head>` ที่คุณประกาศไว้ผ่านคอมโพเนนต์ต่าง ๆ ทั่วทั้งแอปพลิเคชัน แล้วนำไปแทรกลงในส่วน `<head>` ของเอกสาร HTML ตัวจริงในขั้นตอนสุดท้าย

แต่นี่อาจเป็นการพูดเกริ่นล่วงหน้าเร็วไปสักนิด เพราะเรายังไม่ได้ลงลึกเรื่องการเรนเดอร์ฝั่งเซิร์ฟเวอร์อย่างเป็นทางการ ในบทถัดไป เราจะมาดูเรื่องการผสานการทำงานร่วมกับไลบรารี JavaScript กันก่อน จากนั้นเราจะสรุปเนื้อหาฝั่งไคลเอนต์ แล้วค่อยก้าวเข้าสู่โลกของการเรนเดอร์ฝั่งเซิร์ฟเวอร์อย่างเต็มตัว
