# คอมโพเนนต์ `<A/>`

การนำทางฝั่งไคลเอนต์ทำงานได้อย่างสมบูรณ์แบบกับเอลิเมนต์ `<a>` ของ HTML ธรรมดา เราเตอร์จะเพิ่มตัวรับฟังที่จัดการทุกการคลิกบนเอลิเมนต์ `<a>` และพยายามจัดการมันฝั่งไคลเอนต์ กล่าวคือ โดยไม่ต้องเดินทางไปกลับเซิร์ฟเวอร์อีกรอบเพื่อขอ HTML นี่คือสิ่งที่ทำให้เกิดการนำทางแบบ “ซิงเกิลเพจแอป” ที่ฉับไว ซึ่งคุณคงคุ้นเคยจากเว็บแอปสมัยใหม่ส่วนใหญ่

เราเตอร์จะถอนตัวจากการจัดการคลิก `<a>` ในหลายสถานการณ์

- เหตุการณ์คลิกมีการเรียก `prevent_default()` กับมันไว้แล้ว
- ปุ่ม <kbd>Meta</kbd>, <kbd>Alt</kbd>, <kbd>Ctrl</kbd> หรือ <kbd>Shift</kbd> ถูกกดค้างไว้ระหว่างคลิก
- `<a>` มีแอตทริบิวต์ `target` หรือ `download` หรือ `rel="external"`
- ลิงก์มีต้นทางต่างจากตำแหน่งปัจจุบัน

พูดอีกอย่างคือ เราเตอร์จะพยายามทำการนำทางฝั่งไคลเอนต์เฉพาะเมื่อมันค่อนข้างแน่ใจว่าจัดการได้ และมันจะอัปเกรดทุกเอลิเมนต์ `<a>` ให้ได้พฤติกรรมพิเศษนี้

> นี่หมายความว่าหากคุณจำเป็นต้องเลือกที่จะไม่ใช้การจัดเส้นทางฝั่งไคลเอนต์ คุณก็ทำได้ง่ายๆ ตัวอย่างเช่น หากคุณมีลิงก์ไปยังหน้าอื่นบนโดเมนเดียวกัน แต่ไม่ได้เป็นส่วนหนึ่งของแอป Leptos ของคุณ คุณก็แค่ใช้ `<a rel="external">` เพื่อบอกเราเตอร์ว่ามันไม่ใช่สิ่งที่เราเตอร์จัดการได้

เราเตอร์ยังมีคอมโพเนนต์ [`<A>`](https://docs.rs/leptos_router/latest/leptos_router/components/fn.A.html) ซึ่งทำสิ่งเพิ่มเติมสองอย่าง:

1. แก้ไขเส้นทางแบบซ้อนแบบสัมพัทธ์ได้อย่างถูกต้อง การจัดเส้นทางแบบสัมพัทธ์ด้วยแท็ก `<a>` ธรรมดาอาจยุ่งยาก ตัวอย่างเช่น หากคุณมีเส้นทางอย่าง `/post/:id` แล้ว `<A href="1">` จะสร้างเส้นทางสัมพัทธ์ที่ถูกต้อง แต่ `<a href="1">` มักจะไม่ (ขึ้นอยู่กับว่ามันปรากฏที่ไหนในวิวของคุณ) `<A/>` จะแก้ไขเส้นทางโดยอ้างอิงกับพาธของเส้นทางแบบซ้อนที่มันปรากฏอยู่
2. ตั้งค่าแอตทริบิวต์ `aria-current` เป็น `page` หากลิงก์นี้เป็นลิงก์ที่ทำงานอยู่ (กล่าวคือ เป็นลิงก์ไปยังหน้าที่คุณอยู่) ซึ่งมีประโยชน์ต่อการเข้าถึง (accessibility) และการจัดสไตล์ ตัวอย่างเช่น หากคุณต้องการตั้งสีลิงก์ให้ต่างออกไปเมื่อมันเป็นลิงก์ไปยังหน้าที่คุณอยู่ปัจจุบัน คุณก็จับคู่แอตทริบิวต์นี้ด้วยซีเล็กเตอร์ CSS ได้

## การนำทางด้วยโปรแกรม

วิธีนำทางระหว่างหน้าเพจที่คุณใช้บ่อยที่สุดควรเป็นการใช้เอลิเมนต์ `<a>` และ `<form>` หรือคอมโพเนนต์ `<A/>` และ `<Form/>` ที่ถูกเสริมความสามารถ การใช้ลิงก์และฟอร์มในการนำทางเป็นทางออกที่ดีที่สุดสำหรับการเข้าถึงและการลดทอนอย่างสง่างาม

อย่างไรก็ตาม ในบางครั้ง คุณอาจต้องการนำทางด้วยโปรแกรม กล่าวคือ เรียกฟังก์ชันที่นำทางไปยังหน้าใหม่ ในกรณีนั้น คุณควรใช้ฟังก์ชัน [`use_navigate`](https://docs.rs/leptos_router/latest/leptos_router/hooks/fn.use_navigate.html)

```rust
let navigate = leptos_router::hooks::use_navigate();
navigate("/somewhere", Default::default());
```

> คุณแทบไม่ควรทำอะไรอย่าง `<button on:click=move |_| navigate(/* ... */)>` ทุก `on:click` ที่ทำการนำทางควรเป็น `<a>` ด้วยเหตุผลด้านการเข้าถึง

อาร์กิวเมนต์ตัวที่สองตรงนี้คือชุด [`NavigateOptions`](https://docs.rs/leptos_router/latest/leptos_router/struct.NavigateOptions.html) ซึ่งรวมตัวเลือกในการแก้ไขการนำทางโดยอ้างอิงกับเส้นทางปัจจุบันเหมือนที่คอมโพเนนต์ `<A/>` ทำ แทนที่มันในสแต็กการนำทาง ใส่สถานะการนำทางบางอย่าง และคงสถานะการเลื่อนปัจจุบันไว้เมื่อนำทาง

> อีกครั้ง นี่คือตัวอย่างเดิม ลองดูคอมโพเนนต์ `<A/>` แบบสัมพัทธ์ และดู CSS ใน `index.html` เพื่อดูการจัดสไตล์ตาม ARIA

```rust
use leptos::prelude::*;
use leptos_router::components::{Outlet, ParentRoute, Route, Router, Routes, A};
use leptos_router::hooks::use_params_map;
use leptos_router::path;

#[component]
pub fn App() -> impl IntoView {
    view! {
        <Router>
            <h1>"Contact App"</h1>
            // this <nav> will show on every route,
            // because it's outside the <Routes/>
            // note: we can just use normal <a> tags
            // and the router will use client-side navigation
            <nav>
                <a href="/">"Home"</a>
                <a href="/contacts">"Contacts"</a>
            </nav>
            <main>
                <Routes fallback=|| "Not found.">
                    // / just has an un-nested "Home"
                    <Route path=path!("/") view=|| view! {
                        <h3>"Home"</h3>
                    }/>
                    // /contacts has nested routes
                    <ParentRoute
                        path=path!("/contacts")
                        view=ContactList
                      >
                        // if no id specified, fall back
                        <ParentRoute path=path!(":id") view=ContactInfo>
                            <Route path=path!("") view=|| view! {
                                <div class="tab">
                                    "(Contact Info)"
                                </div>
                            }/>
                            <Route path=path!("conversations") view=|| view! {
                                <div class="tab">
                                    "(Conversations)"
                                </div>
                            }/>
                        </ParentRoute>
                        // if no id specified, fall back
                        <Route path=path!("") view=|| view! {
                            <div class="select-user">
                                "Select a user to view contact info."
                            </div>
                        }/>
                    </ParentRoute>
                </Routes>
            </main>
        </Router>
    }
}

#[component]
fn ContactList() -> impl IntoView {
    view! {
        <div class="contact-list">
            // here's our contact list component itself
            <h3>"Contacts"</h3>
            <div class="contact-list-contacts">
                <A href="alice">"Alice"</A>
                <A href="bob">"Bob"</A>
                <A href="steve">"Steve"</A>
            </div>

            // <Outlet/> will show the nested child route
            // we can position this outlet wherever we want
            // within the layout
            <Outlet/>
        </div>
    }
}

#[component]
fn ContactInfo() -> impl IntoView {
    // we can access the :id param reactively with `use_params_map`
    let params = use_params_map();
    let id = move || params.read().get("id").unwrap_or_default();

    // imagine we're loading data from an API here
    let name = move || match id().as_str() {
        "alice" => "Alice",
        "bob" => "Bob",
        "steve" => "Steve",
        _ => "User not found.",
    };

    view! {
        <h4>{name}</h4>
        <div class="contact-info">
            <div class="tabs">
                <A href="" exact=true>"Contact Info"</A>
                <A href="conversations">"Conversations"</A>
            </div>

            // <Outlet/> here is the tabs that are nested
            // underneath the /contacts/:id route
            <Outlet/>
        </div>
    }
}

fn main() {
    leptos::mount::mount_to_body(App)
}
```
