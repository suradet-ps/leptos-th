# เราเตอร์

## พื้นฐาน

ระบบการจัดเส้นทาง (Routing) เป็นกลไกขับเคลื่อนหลักของเว็บไซต์แทบทุกแห่ง โดยเราเตอร์ (router) คือคำตอบของคำถามที่ว่า "เมื่อผู้ใช้เปิด URL นี้ ควรจะมีอะไรแสดงผลบนหน้าเว็บ?"

URL ประกอบไปด้วยหลายส่วน ตัวอย่างเช่น URL `https://my-cool-blog.com/blog/search?q=Search#results` ประกอบด้วย:

- _สคีมา (scheme)_: `https`
- _โดเมน (domain)_: `my-cool-blog.com`
- **พาธ (path)**: `/blog/search`
- **คิวรี (query)** (หรือ **search**): `?q=Search`
- _แฮช (hash)_: `#results`

เราเตอร์ของ Leptos ทำงานร่วมกับส่วนของพาธและคิวรี (`/blog/search?q=Search`) โดยพิจารณาว่าเมื่อได้รับ URL ส่วนนี้ แอปพลิเคชันควรเรนเดอร์สิ่งใดขึ้นมาบนหน้าเว็บ

## ปรัชญา

ในกรณีส่วนใหญ่ พาธควรเป็นตัวกำหนดสิ่งที่แสดงผลบนหน้าเว็บ จากมุมมองของผู้ใช้งาน สำหรับแอปพลิเคชันส่วนใหญ่แล้ว การเปลี่ยนแปลงสถานะที่สำคัญของแอปควรจะสะท้อนอยู่ใน URL เสมอ หากคุณคัดลอก URL นั้นไปวางในแท็บใหม่ คุณควรจะได้เห็นหน้าจอที่เหมือนหรือใกล้เคียงกับของเดิม

ในแง่นี้ เราเตอร์จึงเปรียบเสมือนหัวใจสำคัญของการจัดการสถานะส่วนกลาง (global state management) ของแอปพลิเคชันอย่างแท้จริง เพราะมันเป็นตัวขับเคลื่อนหลักว่าสิ่งใดควรจะแสดงผลบนหน้าจอ

เราเตอร์จะจัดการงานส่วนใหญ่เหล่านี้ให้คุณโดยอัตโนมัติ โดยการจับคู่ (map) ตำแหน่งปัจจุบันเข้ากับคอมโพเนนต์ที่สอดคล้องกัน
