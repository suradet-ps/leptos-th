# เราเตอร์

## พื้นฐาน

การจัดเส้นทางขับเคลื่อนเว็บไซต์ส่วนใหญ่ เราเตอร์คือคำตอบของคำถามที่ว่า “เมื่อได้ URL นี้ ควรมีอะไรปรากฏบนหน้าเพจ?”

URL ประกอบด้วยหลายส่วน ตัวอย่างเช่น URL `https://my-cool-blog.com/blog/search?q=Search#results` ประกอบด้วย

- _สคีมา (scheme)_: `https`
- _โดเมน (domain)_: `my-cool-blog.com`
- **พาธ (path)**: `/blog/search`
- **ควิรี (query)** (หรือ **search**): `?q=Search`
- _แฮช (hash)_: `#results`

เราเตอร์ของ Leptos ทำงานกับพาธและควิรี (`/blog/search?q=Search`) เมื่อพิจารณา URL ส่วนนี้ แอปควรเรนเดอร์อะไรบนหน้าเพจ?

## ปรัชญา

ในกรณีส่วนใหญ่ พาธควรเป็นตัวกำหนดสิ่งที่แสดงบนหน้าเพจ จากมุมมองของผู้ใช้ สำหรับแอปพลิเคชันส่วนใหญ่ การเปลี่ยนแปลงครั้งสำคัญของสถานะแอปควรสะท้อนอยู่ใน URL หากคุณคัดลอก URL ไปวางแล้วเปิดในแท็บอื่น คุณควรพบว่าตัวเองอยู่ที่เดิมมากหรือน้อย

ในแง่นี้ เราเตอร์จึงเป็นหัวใจของการจัดการสถานะส่วนกลางของแอปพลิเคชันของคุณจริงๆ ยิ่งกว่าสิ่งอื่นใด มันเป็นตัวกำหนดสิ่งที่แสดงบนหน้าเพจ

เราเตอร์จัดการงานส่วนใหญ่เหล่านี้ให้คุณ โดยการแมปตำแหน่งปัจจุบันไปยังคอมโพเนนต์ที่เจาะจง
