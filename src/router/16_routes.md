# การนิยามเส้นทาง

## เริ่มต้นใช้งาน

การเริ่มต้นใช้งานเราเตอร์นั้นง่ายมาก

อย่างแรกเลย ตรวจสอบให้แน่ใจว่าคุณได้เพิ่มแพ็กเกจ `leptos_router` ลงในดีเพนเดนซีของคุณแล้ว ต่างจาก `leptos` ตรงที่มันไม่มีฟีเจอร์ `csr` และ `hydrate` แยกกัน แต่มันมีฟีเจอร์ `ssr` ที่ตั้งใจให้ใช้เฉพาะฝั่งเซิร์ฟเวอร์ ดังนั้นให้เปิดใช้งานฟีเจอร์นั้นสำหรับบิลด์ฝั่งเซิร์ฟเวอร์ของคุณ

> สิ่งสำคัญคือเราเตอร์เป็นแพ็กเกจแยกจากตัว `leptos` เอง นั่นหมายความว่าทุกอย่างในเราเตอร์สามารถนิยามได้ในโค้ดฝั่งผู้ใช้ หากคุณต้องการสร้างเราเตอร์ของคุณเอง หรือไม่ใช้เราเตอร์เลย คุณมีอิสระเต็มที่ที่จะทำเช่นนั้น!

และนำเข้าชนิดข้อมูลที่เกี่ยวข้องจากเราเตอร์ ด้วยอะไรประมาณนี้

```rust
use leptos_router::components::{Router, Route, Routes};
```

## การจัดเตรียม `<Router/>`

พฤติกรรมการจัดเส้นทางถูกจัดเตรียมโดยคอมโพเนนต์ [`<Router/>`](https://docs.rs/leptos_router/latest/leptos_router/components/fn.Router.html) ซึ่งโดยปกติควรอยู่ที่ใดที่หนึ่งใกล้รากของแอปพลิเคชันของคุณ โดยห่อส่วนที่เหลือของแอปไว้

> คุณไม่ควรพยายามใช้ `<Router/>` หลายตัวในแอปของคุณ จำไว้ว่าเราเตอร์ขับเคลื่อนสถานะส่วนกลาง: หากคุณมีเราเตอร์หลายตัว ตัวไหนจะเป็นตัวตัดสินว่าต้องทำอะไรเมื่อ URL เปลี่ยน?

มาเริ่มจากคอมโพเนนต์ `<App/>` ง่ายๆ ที่ใช้เราเตอร์กัน:

```rust
use leptos::prelude::*;
use leptos_router::components::Router;

#[component]
pub fn App() -> impl IntoView {
    view! {
      <Router>
        <nav>
          /* ... */
        </nav>
        <main>
          /* ... */
        </main>
      </Router>
    }
}

```

## การนิยาม `<Routes/>`

คอมโพเนนต์ [`<Routes/>`](https://docs.rs/leptos_router/latest/leptos_router/components/fn.Routes.html) คือที่ที่คุณนิยามเส้นทางทั้งหมดที่ผู้ใช้สามารถนำทางไปได้ในแอปพลิเคชันของคุณ เส้นทางที่เป็นไปได้แต่ละเส้นทางถูกนิยามด้วยคอมโพเนนต์ [`<Route/>`](https://docs.rs/leptos_router/latest/leptos_router/components/fn.Route.html)

คุณควรวางคอมโพเนนต์ `<Routes/>` ไว้ที่ตำแหน่งในแอปของคุณที่คุณต้องการให้เส้นทางถูกเรนเดอร์ ทุกอย่างที่อยู่นอก `<Routes/>` จะปรากฏอยู่บนทุกหน้าเพจ ดังนั้นคุณจึงปล่อยสิ่งอย่างแถบนำทางหรือเมนูไว้ด้านนอก `<Routes/>` ได้

```rust
use leptos::prelude::*;
use leptos_router::components::*;

#[component]
pub fn App() -> impl IntoView {
    view! {
      <Router>
        <nav>
          /* ... */
        </nav>
        <main>
          // all our routes will appear inside <main>
          <Routes fallback=|| "Not found.">
            /* ... */
          </Routes>
        </main>
      </Router>
    }
}
```

`<Routes/>` ควรมี `fallback` ด้วย ซึ่งเป็นฟังก์ชันที่นิยามว่าควรแสดงอะไรหากไม่มีเส้นทางใดตรงกัน

เส้นทางแต่ละเส้นทางถูกนิยามโดยการส่ง children ให้ `<Routes/>` ด้วยคอมโพเนนต์ `<Route/>` โดย `<Route/>` รับ `path` และ `view` เมื่อตำแหน่งปัจจุบันตรงกับ `path` ตัว `view` จะถูกสร้างและแสดง

`path` นิยามได้ง่ายที่สุดโดยใช้มาโคร `path` และสามารถประกอบด้วย

- พาธแบบคงที่ (`/users`),
- พารามิเตอร์แบบมีชื่อและไดนามิกที่เริ่มต้นด้วยเครื่องหมายทวิภาค (`/:id`),
- และ/หรือไวลด์การ์ดที่เริ่มต้นด้วยเครื่องหมายดอกจัน (`/user/*any`)

`view` เป็นฟังก์ชันที่คืนค่าวิว คอมโพเนนต์ใดก็ได้ที่ไม่มีพร็อพใช้ได้ที่นี่ เช่นเดียวกับโคลเชอร์ที่คืนค่าวิวบางอย่าง

```rust
<Routes fallback=|| "Not found.">
  <Route path=path!("/") view=Home/>
  <Route path=path!("/users") view=Users/>
  <Route path=path!("/users/:id") view=UserProfile/>
  <Route path=path!("/*any") view=|| view! { <h1>"Not Found"</h1> }/>
</Routes>
```

> `view` รับ `Fn() -> impl IntoView` หากคอมโพเนนต์ไม่มีพร็อพ ก็สามารถส่งเข้าไปใน `view` ได้โดยตรง ในกรณีนี้ `view=Home` เป็นเพียงรูปแบบย่อของ `view=|| view! { <Home/> }`

ตอนนี้ หากคุณนำทางไปที่ `/` หรือ `/users` คุณจะได้หน้าแรกหรือ `<Users/>` หากคุณไปที่ `/users/3` หรือ `/blahblah` คุณจะได้โปรไฟล์ผู้ใช้หรือหน้า 404 ของคุณ (`<NotFound/>`) ในการนำทางทุกครั้ง เราเตอร์จะตัดสินว่า `<Route/>` ตัวใดควรถูกจับคู่ และดังนั้นเนื้อหาใดควรถูกแสดง ณ ที่ที่นิยามคอมโพเนนต์ `<Routes/>`
