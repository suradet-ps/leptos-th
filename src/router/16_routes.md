# การนิยามเส้นทาง

## เริ่มต้นใช้งาน

การเริ่มต้นใช้งานเราเตอร์นั้นง่ายมาก

อันดับแรก ตรวจสอบให้แน่ใจว่าคุณได้เพิ่มแพ็กเกจ `leptos_router` ลงใน dependencies ของโปรเจกต์แล้ว ซึ่งต่างจาก `leptos` ตรงที่ตัวมันไม่ได้มีฟีเจอร์แยกเป็น `csr` และ `hydrate` แต่จะมีฟีเจอร์ `ssr` ที่ออกแบบมาสำหรับใช้งานบนฝั่งเซิร์ฟเวอร์โดยเฉพาะ ดังนั้นอย่าลืมเปิดใช้งานฟีเจอร์ดังกล่าวสำหรับบิลด์ฝั่งเซิร์ฟเวอร์ของคุณ

> ข้อสำคัญคือ เราเตอร์เป็นแพ็กเกจที่แยกต่างหากจากตัว `leptos` เอง นั่นหมายความว่าทุกสิ่งในเราเตอร์สามารถนิยามขึ้นได้ในโค้ดฝั่งผู้ใช้ (user-land code) หากคุณต้องการสร้างเราเตอร์ขึ้นมาใช้เอง หรือเลือกที่จะไม่ใช้เราเตอร์เลย ก็สามารถทำได้อย่างอิสระเต็มที่!

จากนั้น ให้นำเข้าชนิดข้อมูลที่เกี่ยวข้องจากเราเตอร์ โดยเขียนทำนองนี้:

```rust
use leptos_router::components::{Router, Route, Routes};
```

## การจัดเตรียม `<Router/>`

พฤติกรรมของระบบเราติงจะถูกจัดเตรียมโดยคอมโพเนนต์ [`<Router/>`](https://docs.rs/leptos_router/latest/leptos_router/components/fn.Router.html) ซึ่งตามปกติแล้วควรวางไว้ที่ใดที่หนึ่งใกล้กับรูทของแอปพลิเคชัน โดยทำหน้าที่ห่อหุ้มส่วนที่เหลือทั้งหมดของแอปไว้

> คุณไม่ควรพยายามใช้ `<Router/>` หลายตัวภายในแอปเดียวกัน โปรดจำไว้ว่าเราเตอร์ทำหน้าที่ขับเคลื่อนสถานะส่วนกลาง: หากคุณมีเราเตอร์หลายตัว ตัวใดเล่าจะเป็นผู้ตัดสินใจว่าจะต้องทำสิ่งใดเมื่อ URL เกิดการเปลี่ยนแปลง?

เรามาเริ่มต้นจากคอมโพเนนต์ `<App/>` แบบง่าย ๆ ที่ใช้งานเราเตอร์กัน:

```rust
use leptos::prelude::*;
use leptos_router::components::Router;

#[component]
pub fn App() -> impl IntoView {
    view! {
      <Router>
        <nav>
          /* ... */
        </nav>
        <main>
          /* ... */
        </main>
      </Router>
    }
}

```

## การนิยาม `<Routes/>`

คอมโพเนนต์ [`<Routes/>`](https://docs.rs/leptos_router/latest/leptos_router/components/fn.Routes.html) คือตำแหน่งที่คุณใช้นิยามเส้นทางทั้งหมดที่ผู้ใช้สามารถนำทางไปได้ในแอปพลิเคชันของคุณ โดยแต่ละเส้นทางที่เป็นไปได้จะถูกนิยามผ่านคอมโพเนนต์ [`<Route/>`](https://docs.rs/leptos_router/latest/leptos_router/components/fn.Route.html)

คุณควรวางคอมโพเนนต์ `<Routes/>` ไว้ตรงตำแหน่งในแอปที่คุณต้องการให้เส้นทางนั้น ๆ ถูกเรนเดอร์ออกมา ส่วนประกอบทุกอย่างที่อยู่นอก `<Routes/>` จะคงอยู่บนทุก ๆ หน้าเพจเสมอ ดังนั้นคุณจึงสามารถวางส่วนประกอบจำพวกแถบนำทาง (navigation bar) หรือเมนูไว้ข้างนอก `<Routes/>` ได้

```rust
use leptos::prelude::*;
use leptos_router::components::*;

#[component]
pub fn App() -> impl IntoView {
    view! {
      <Router>
        <nav>
          /* ... */
        </nav>
        <main>
          // all our routes will appear inside <main>
          <Routes fallback=|| "Not found.">
            /* ... */
          </Routes>
        </main>
      </Router>
    }
}
```

`<Routes/>` ควรมีพร็อพ `fallback` ด้วย ซึ่งเป็นฟังก์ชันที่ระบุว่าจะให้แสดงผลอะไรขึ้นมาหากไม่มีเส้นทางใดตรงกับ URL ปัจจุบัน

เส้นทางแต่ละเส้นทางจะถูกนิยามขึ้นโดยการส่งคอมโพเนนต์ลูกเข้าไปใน `<Routes/>` ด้วยคอมโพเนนต์ `<Route/>` โดย `<Route/>` จะรับ `path` และ `view` เมื่อตำแหน่ง URL ปัจจุบันตรงกับ `path` ดังกล่าว ตัว `view` ก็จะถูกสร้างและแสดงผลขึ้นมา

`path` นั้นสามารถนิยามได้สะดวกที่สุดผ่านการใช้แมโคร `path!` และสามารถประกอบไปด้วย:

- พาธแบบคงที่ (`/users`),
- พารามิเตอร์แบบไดนามิกที่มีการตั้งชื่อ โดยขึ้นต้นด้วยเครื่องหมายทวิภาค (`/:id`),
- และ/หรือไวลด์การ์ด (wildcard) ที่ขึ้นต้นด้วยเครื่องหมายดอกจัน (`/user/*any`)

`view` คือฟังก์ชันที่คืนค่าเป็นวิว โดยคอมโพเนนต์ใด ๆ ที่ไม่มีพร็อพสามารถนำมาส่งต่อที่นี่ได้ทันที เช่นเดียวกับโคลเชอร์ที่คืนค่าวิดีโอหรือวิวบางอย่าง

```rust
<Routes fallback=|| "Not found.">
  <Route path=path!("/") view=Home/>
  <Route path=path!("/users") view=Users/>
  <Route path=path!("/users/:id") view=UserProfile/>
  <Route path=path!("/*any") view=|| view! { <h1>"Not Found"</h1> }/>
</Routes>
```

> `view` รับค่าเป็น `Fn() -> impl IntoView` หากคอมโพเนนต์ไม่มีพร็อพ ก็สามารถส่งเข้าไปใน `view` ได้โดยตรง ในกรณีนี้ `view=Home` จึงเป็นเพียงรูปย่อของ `view=|| view! { <Home/> }`

เพียงเท่านี้ หากคุณนำทางไปยัง `/` หรือ `/users` คุณก็จะได้เห็นหน้าแรกหรือคอมโพเนนต์ `<Users/>` หากคุณไปยัง `/users/3` หรือ `/blahblah` คุณก็จะได้เห็นโปรไฟล์ผู้ใช้ หรือหน้า 404 ของคุณ (`<NotFound/>`) ในทุก ๆ การนำทาง เราเตอร์จะเป็นผู้ตัดสินว่าควรจับคู่กับ `<Route/>` ตัวใด และด้วยเหตุนี้ เนื้อหาใดจึงควรถูกนำมาแสดงผล ณ ตำแหน่งที่นิยามคอมโพเนนต์ `<Routes/>` เอาไว้
