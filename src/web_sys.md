# การผสานรวมกับ JavaScript: `wasm-bindgen`, `web_sys` และ `HtmlElement`

Leptos มีเครื่องมือหลากหลายที่ช่วยให้คุณสร้างเว็บแอปพลิเคชันแบบประกาศได้โดยไม่ต้องออกจากโลก
ของเฟรมเวิร์ก สิ่งต่างๆ อย่างระบบรีแอกทีฟ มาโคร `component` และ `view` และเราเตอร์ ช่วยให้คุณสร้าง
ส่วนติดต่อผู้ใช้โดยไม่ต้องโต้ตอบกับเว็บ API ที่เบราว์เซอร์มีให้โดยตรง และทั้งหมดนี้คุณทำได้
ใน Rust โดยตรง ซึ่งยอดเยี่ยมมาก—สมมติว่าคุณชอบ Rust นะ (และถ้าคุณอ่านมาถึงตรงนี้ในหนังสือเล่มนี้ เราก็
สันนิษฐานว่าคุณชอบ Rust)

ครีตในระบบนิเวศอย่างชุดยูทิลิตีอันยอดเยี่ยมที่ [`leptos-use`](https://leptos-use.rs/) มีให้สามารถพาคุณ
ไปได้ไกลยิ่งขึ้น ด้วยการห่อเว็บ API หลายตัวด้วยตัวห่อรีแอกทีฟเฉพาะสำหรับ Leptos

อย่างไรก็ตาม ในหลายกรณีคุณจะต้องเข้าถึงไลบรารี JavaScript หรือเว็บ API โดยตรง บทนี้ช่วยคุณได้

## การใช้ไลบรารี JS กับ `wasm-bindgen`

โค้ด Rust ของคุณสามารถคอมไพล์เป็นโมดูล WebAssembly (WASM) และโหลดไปรันในเบราว์เซอร์ได้ อย่างไรก็ตาม WASM ไม่
สามารถเข้าถึง API ของเบราว์เซอร์ได้โดยตรง แต่ระบบนิเวศ Rust/WASM อาศัยการสร้างไบน์ดิงจากโค้ด Rust ของคุณ
ไปยังสภาพแวดล้อม JavaScript ของเบราว์เซอร์ที่โฮสต์มันอยู่

ครีต [`wasm-bindgen`](https://rustwasm.github.io/docs/wasm-bindgen/) อยู่ตรงศูนย์กลางของระบบนิเวศนั้น มันมี
ทั้งอินเทอร์เฟซสำหรับทำเครื่องหมายบางส่วนของโค้ด Rust ด้วยแอนโนเทชันเพื่อบอกว่าควรเรียก JS อย่างไร และเครื่องมือ CLI สำหรับสร้าง
โค้ดกลู JS ที่จำเป็น คุณใช้มันมาตลอดโดยไม่รู้ตัว: ทั้ง `trunk` และ `cargo-leptos` ต่างก็พึ่งพา
`wasm-bindgen` อยู่เบื้องหลัง

หากมีไลบรารี JavaScript ที่คุณต้องการเรียกจาก Rust คุณควรดูเอกสารของ `wasm-bindgen` เรื่อง
[การนำเข้าฟังก์ชันจาก JS](https://rustwasm.github.io/docs/wasm-bindgen/examples/import-js.html) การนำเข้าฟังก์ชัน คลาส หรือค่าทีละรายการ
จาก JavaScript มาใช้ในแอป Rust ของคุณนั้นค่อนข้างง่าย

การผสานรวมไลบรารี JS เข้ากับแอปของคุณโดยตรงนั้นไม่ใช่เรื่องง่ายเสมอไป โดยเฉพาะไลบรารีที่ขึ้นอยู่กับ
เฟรมเวิร์ก JS เฉพาะอย่าง React อาจผสานรวมได้ยาก ไลบรารีที่จัดการสถานะ DOM ในทางใดทางหนึ่ง (เช่น
ตัวแก้ไขข้อความแบบ rich text) ก็ควรใช้อย่างระมัดระวังเช่นกัน: ทั้ง Leptos และไลบรารี JS นั้นน่าจะถือว่า
ตัวเองเป็นแหล่งความจริงสูงสุดสำหรับสถานะของแอป ดังนั้นคุณควรแยกความรับผิดชอบของทั้งสองออกจากกันอย่างระมัดระวัง

## การเข้าถึงเว็บ API ด้วย `web-sys`

ถ้าคุณแค่ต้องการเข้าถึง API ของเบราว์เซอร์บางตัวโดยไม่ต้องดึงไลบรารี JS แยกต่างหาก คุณสามารถใช้
ครีต [`web_sys`](https://docs.rs/web-sys/latest/web_sys/) ได้ มันมีไบน์ดิงสำหรับเว็บ API ทั้งหมดที่
เบราว์เซอร์มีให้ โดยแมปชนิดข้อมูลและฟังก์ชันของเบราว์เซอร์เป็นสตรักต์และเมธอดของ Rust แบบ 1:1

โดยทั่วไป หากคุณถามว่า “ฉันจะ_ทำ X_ กับ Leptos ได้อย่างไร?” โดยที่ _ทำ X_ คือการเข้าถึงเว็บ API บางตัว การค้นหาวิธีแก้
ด้วย JavaScript ล้วนๆ แล้วแปลเป็น Rust โดยใช้[เอกสาร `web-sys`](https://docs.rs/web-sys/latest/web_sys/) ถือเป็น
วิธีที่ดี

> หลังจากส่วนนี้ คุณอาจพบว่า
> [บทว่าด้วย `web-sys` ในคู่มือ `wasm-bindgen`](https://rustwasm.github.io/docs/wasm-bindgen/web-sys/index.html)
> มีประโยชน์สำหรับการอ่านเพิ่มเติม

### การเปิดใช้งานฟีเชอร์

`web_sys` ถูกควบคุมด้วยฟีเชอร์อย่างเข้มงวดเพื่อให้เวลาคอมไพล์ต่ำ หากคุณต้องการใช้ API มากมายของมัน คุณอาจ
ต้องเปิดใช้งานฟีเชอร์เพื่อใช้มัน

ฟีเชอร์ที่จำเป็นสำหรับการใช้ไอเท็มหนึ่งๆ จะระบุไว้ในเอกสารของมันเสมอ
ตัวอย่างเช่น หากต้องการใช้ [`Element::get_bounding_rect_client`](https://docs.rs/web-sys/latest/web_sys/struct.Element.html#method.get_bounding_client_rect) คุณต้องเปิดใช้งานฟีเชอร์ `DomRect` และ `Element`

Leptos เปิดใช้งาน[ฟีเชอร์จำนวนมาก](https://github.com/leptos-rs/leptos/blob/main/leptos_dom/Cargo.toml#L41)ไว้แล้ว - หากฟีเชอร์ที่ต้องการถูกเปิดใช้งานไว้ที่นี่แล้ว คุณก็ไม่ต้องเปิดมันในแอปของคุณเอง
ไม่เช่นนั้น ให้เพิ่มมันลงใน `Cargo.toml` ของคุณ แล้วคุณก็พร้อมลุยได้เลย!

```toml
[dependencies.web-sys]
version = "0.3"
features = ["DomRect"]
```

อย่างไรก็ตาม เมื่อมาตรฐาน JavaScript พัฒนาไปและ API ต่างๆ ถูกเขียนขึ้น คุณอาจต้องการใช้ฟีเจอร์ของเบราว์เซอร์ที่ในทางเทคนิคยังไม่เสถียรเต็มที่ เช่น [WebGPU](https://docs.rs/web-sys/latest/web_sys/struct.Gpu.html)
`web_sys` จะตามมาตรฐานที่ (อาจเปลี่ยนแปลงบ่อยครั้ง) ซึ่งหมายความว่าไม่มีการรับประกันความเสถียรใดๆ

ในการใช้สิ่งนี้ คุณต้องเพิ่ม `RUSTFLAGS=--cfg=web_sys_unstable_apis` เป็นตัวแปรสภาพแวดล้อม
ซึ่งทำได้โดยเพิ่มมันในทุกคำสั่ง หรือเพิ่มลงใน `.cargo/config.toml` ในที่เก็บโค้ดของคุณ

ในฐานะส่วนหนึ่งของคำสั่ง:

```sh
RUSTFLAGS=--cfg=web_sys_unstable_apis cargo # ...
```

ใน `.cargo/config.toml`:

```toml
[env]
RUSTFLAGS = "--cfg=web_sys_unstable_apis"
```

## การเข้าถึง `HtmlElement` ดิบจาก `view` ของคุณ

สไตล์แบบประกาศของเฟรมเวิร์กหมายความว่าคุณไม่จำเป็นต้องจัดการโหนด DOM โดยตรงเพื่อสร้างส่วนติดต่อผู้ใช้ของคุณ
อย่างไรก็ตาม ในบางกรณีคุณต้องการเข้าถึงเอลิเมนต์ DOM ภายใต้ที่แทนส่วนหนึ่งของวิวของคุณโดยตรง ส่วนของหนังสือ
เกี่ยวกับ[“อินพุตแบบไม่ควบคุม”](view/05_forms.html?highlight=NodeRef#อินพุตแบบไมควบคุม-uncontrolled-inputs) ได้แสดงวิธีทำโดยใช้
ชนิด [`NodeRef`](https://docs.rs/leptos/latest/leptos/tachys/reactive_graph/node_ref/struct.NodeRef.html)

`NodeRef::get` คืนค่าเอลิเมนต์ `web-sys` ที่มีชนิดถูกต้อง
ซึ่งสามารถจัดการได้โดยตรง

ตัวอย่างเช่น ลองพิจารณาโค้ดต่อไปนี้:

```rust
#[component]
pub fn App() -> impl IntoView {
    let node_ref = NodeRef::<Input>::new();

    Effect::new(move |_| {
        if let Some(node) = node_ref.get() {
            leptos::logging::log!("value = {}", node.value());
        }
    });

    view! {
        <input node_ref=node_ref/>
    }
}
```

ภายในเอฟเฟกต์ตรงนี้ `node` ก็แค่ `web_sys::HtmlInputElement` ธรรมดาๆ สิ่งนี้ทำให้เราเรียกเมธอดที่เหมาะสมใดๆ ก็ได้

(โปรดทราบว่า `.get()` คืนค่าเป็น `Option` ตรงนี้ เพราะ `NodeRef` จะว่างเปล่าจนกว่าจะถูกเติมเมื่อเอลิเมนต์ DOM ถูกสร้างขึ้นจริงๆ เอฟเฟกต์จะรันหนึ่งทิกหลังจากคอมโพเนนต์รัน ดังนั้นในกรณีส่วนใหญ่ `<input>` จะถูกสร้างเสร็จแล้วก่อนที่เอฟเฟกต์จะรัน)
