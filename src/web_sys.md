# การผสานรวมกับ JavaScript: `wasm-bindgen`, `web_sys` และ `HtmlElement`

Leptos ได้จัดเตรียมเครื่องมืออันหลากหลายที่ช่วยให้คุณสร้างเว็บแอปพลิเคชันเชิงประกาศ (declarative) ได้อย่างสมบูรณ์โดยไม่ต้องก้าวขาออกจากโลกของตัวเฟรมเวิร์กเลย สิ่งต่าง ๆ เช่น ระบบรีแอกทีฟ, มาโคร `component` และ `view`, รวมถึงระบบเราเตอร์ ช่วยให้คุณสามารถสร้างหน้าตาอินเทอร์เฟซได้โดยไม่ต้องไปยุ่งเกี่ยวกับ Web API ดั้งเดิมของเบราว์เซอร์โดยตรง และที่ยอดเยี่ยมที่สุดคือ คุณสามารถทำทุกอย่างได้ด้วยภาษา Rust ล้วน ๆ—แน่นอนว่านั่นเป็นข้อดีอย่างยิ่งสำหรับคนที่ชื่นชอบ Rust (และหากคุณอ่านมาจนถึงบทนี้ในหนังสือ เราก็มั่นใจว่าคุณย่อมชอบภาษา Rust อย่างแน่นอน)

ยิ่งไปกว่านั้น เครตในระบบนิเวศภายนอกอย่างชุดเครื่องมือสุดเจ๋งจาก [`leptos-use`](https://leptos-use.rs/) ยังช่วยต่อยอดให้คุณทำงานได้สะดวกสบายยิ่งขึ้นไปอีก ด้วยการนำ Web API จำนวนมากมาครอบ (wrap) ไว้ในรูปแบบของพรีมิตีฟรีแอกทีฟสำหรับ Leptos โดยเฉพาะ

อย่างไรก็ตาม ในโลกแห่งความเป็นจริง มีอีกหลายสถานการณ์ที่คุณจำเป็นต้องเข้าถึงไลบรารี JavaScript หรือเรียกใช้ Web API โดยตรง ซึ่งบทเรียนนี้จะช่วยให้คุณทำสิ่งเหล่านั้นได้อย่างมั่นใจ

## การใช้ไลบรารี JS กับ `wasm-bindgen`

โค้ดภาษา Rust ของคุณสามารถคอมไพล์ออกมาเป็นโมดูล WebAssembly (WASM) และโหลดไปสั่งรันบนเบราว์เซอร์ได้ ทว่า WASM นั้นไม่สามารถเข้าถึง API ต่าง ๆ ของเบราว์เซอร์ได้โดยตรง สถาปัตยกรรมของระบบนิเวศ Rust/WASM จึงต้องพึ่งพาการสร้างไบน์ดิง (bindings) เพื่อเชื่อมโยงโค้ด Rust ของคุณเข้ากับสภาพแวดล้อมรันไทม์ของ JavaScript บนเบราว์เซอร์ที่ทำหน้าที่โฮสต์มันอยู่

เครต [`wasm-bindgen`](https://rustwasm.github.io/docs/wasm-bindgen/) ถือเป็นหัวใจสำคัญของระบบนิเวศนี้ โดยมันเตรียมทั้งอินเทอร์เฟซสำหรับกำกับโค้ด Rust ด้วยแอนโนเทชันเพื่อบอกวิธีการเรียกใช้ฟังก์ชัน JS และเครื่องมือ CLI สำหรับสร้างโค้ดตัวเชื่อม (glue code) ฝั่ง JavaScript ที่จำเป็นให้โดยอัตโนมัติ ซึ่งจริง ๆ แล้วคุณได้ใช้งานมันอยู่ตลอดเวลาโดยไม่รู้ตัว เพราะทั้ง `trunk` และ `cargo-leptos` ต่างก็พึ่งพา `wasm-bindgen` อยู่เบื้องหลังทั้งสิ้น

หากมีไลบรารี JavaScript ตัวใดที่คุณต้องการเรียกใช้งานจากโค้ด Rust แนะนำให้ศึกษาจากเอกสารของ `wasm-bindgen` ในหัวข้อ [การนำเข้าฟังก์ชันจาก JS](https://rustwasm.github.io/docs/wasm-bindgen/examples/import-js.html) ซึ่งการอิมพอร์ตฟังก์ชัน, คลาส หรือค่าต่าง ๆ จาก JavaScript ทีละตัวเข้ามาใช้งานในแอป Rust นั้นทำได้ค่อนข้างสะดวกและไม่ซับซ้อน

อย่างไรก็ดี การนำไลบรารี JS เข้ามาผสานรวมเข้ากับแอปของคุณโดยตรงอาจไม่ได้ราบรื่นเสมอไป โดยเฉพาะอย่างยิ่ง ไลบรารีใดก็ตามที่ผูกติดอยู่กับ JS เฟรมเวิร์กตัวอื่น (เช่น React) ย่อมผสานรวมได้ยาก นอกจากนี้ ไลบรารีที่มีการเข้าแทรกแซงและเปลี่ยนแปลงสถานะของ DOM โดยตรง (เช่น rich text editors) ก็ต้องใช้งานด้วยความระมัดระวังเป็นพิเศษ: เพราะทั้ง Leptos และไลบรารี JS ต่างฝ่ายต่างอาจถือว่าตัวเองเป็นแหล่งความจริงสูงสุด (single source of truth) สำหรับสถานะของแอปพลิเคชัน ดังนั้นคุณจึงต้องแบ่งขอบเขตความรับผิดชอบของทั้งสองฝั่งออกจากกันให้ชัดเจน

## การเข้าถึงเว็บ API ด้วย `web-sys`

หากคุณเพียงต้องการเข้าถึง Web API ทั่วไปของเบราว์เซอร์โดยไม่จำเป็นต้องดึงไลบรารี JS ภายนอกเข้ามาใช้งาน คุณสามารถเลือกใช้เครต [`web_sys`](https://docs.rs/web-sys/latest/web_sys/) ได้ทันที โดยเครตนี้จะเตรียมไบน์ดิงสำหรับ Web API ทั้งหมดที่เบราว์เซอร์รองรับ พร้อมทั้งทำการแมปชนิดข้อมูลและฟังก์ชันของเบราว์เซอร์ให้กลายเป็นสตรักต์และเมธอดของภาษา Rust แบบ 1:1

โดยทั่วไปแล้ว หากคุณเกิดคำถามว่า “เราจะ_ทำสิ่งนี้ (X)_ ใน Leptos ได้อย่างไร?” โดยที่ _สิ่งนี้ (X)_ คือการเรียกใช้ Web API ของเบราว์เซอร์ แนวทางที่ดีที่สุดคือการค้นหาตัวอย่างโค้ดที่เขียนด้วย JavaScript ล้วน ๆ ก่อน แล้วจึงค่อยนำมาแปลงเป็นโค้ด Rust โดยอ้างอิงจาก [เอกสารของ web-sys](https://docs.rs/web-sys/latest/web_sys/)

> หลังจากจบบทนี้ คุณอาจพบว่า
> [บทว่าด้วย `web-sys` ในคู่มือ `wasm-bindgen`](https://rustwasm.github.io/docs/wasm-bindgen/web-sys/index.html)
> เป็นแหล่งข้อมูลที่มีประโยชน์อย่างยิ่งสำหรับการศึกษาเพิ่มเติม

### การเปิดใช้งานฟีเชอร์

เครต `web_sys` มีการแบ่งแยกการทำงานด้วยฟีเจอร์แฟล็ก (features) อย่างละเอียด เพื่อช่วยลดระยะเวลาในการคอมไพล์ให้สั้นที่สุด หากคุณต้องการเรียกใช้ API ใด ๆ จากรายการมากมายของมัน คุณอาจจำเป็นต้องเปิดใช้งานฟีเจอร์ที่เกี่ยวข้องก่อนจึงจะสามารถใช้งานได้

ฟีเจอร์ที่จำเป็นต่อการใช้งานแต่ละไอเท็มจะระบุไว้ในเอกสารของไอเท็มนั้นเสมอ ตัวอย่างเช่น หากต้องการใช้เมธอด [`Element::get_bounding_rect_client`](https://docs.rs/web-sys/latest/web_sys/struct.Element.html#method.get_bounding_client_rect) คุณจะต้องเปิดใช้งานฟีเจอร์ `DomRect` และ `Element` ในโปรเจกต์ของคุณ

อย่างไรก็ดี ตัว Leptos เองได้เปิดใช้งาน [ฟีเจอร์จำนวนมาก](https://github.com/leptos-rs/leptos/blob/main/leptos_dom/Cargo.toml#L41) มาให้ล่วงหน้าแล้ว—ซึ่งหากฟีเจอร์ที่คุณต้องการถูกเปิดไว้อยู่แล้ว คุณก็ไม่จำเป็นต้องประกาศเปิดซ้ำในแอปของคุณเอง แต่หากยังไม่มี ให้เพิ่มฟีเจอร์นั้นเข้าไปในไฟล์ `Cargo.toml` แล้วคุณก็พร้อมลุยได้ทันที:

```toml
[dependencies.web-sys]
version = "0.3"
features = ["DomRect"]
```

นอกจากนี้ ในระหว่างที่มาตรฐานของ JavaScript มีการพัฒนาและมี API ใหม่ ๆ เกิดขึ้นอย่างต่อเนื่อง คุณอาจมีความต้องการที่จะทดลองใช้งานฟีเจอร์เบราว์เซอร์ล้ำสมัยที่ยังไม่เสถียรอย่างเต็มตัวในทางเทคนิค เช่น [WebGPU](https://docs.rs/web-sys/latest/web_sys/struct.Gpu.html) ซึ่งทาง `web_sys` จะคอยอัปเดตตามมาตรฐานใหม่เหล่านั้น (ที่อาจเปลี่ยนแปลงได้บ่อยครั้ง) จึงไม่มีการรับประกันความเสถียรของ API ในกลุ่มนี้

ในการเปิดใช้งาน API กลุ่มที่ยังไม่เสถียรนี้ คุณจำเป็นต้องกำหนดตัวแปรสภาพแวดล้อม (environment variable) เป็น `RUSTFLAGS=--cfg=web_sys_unstable_apis` ซึ่งสามารถทำได้โดยการใส่แฟล็กนี้ไว้ข้างหน้าทุกคำสั่ง cargo หรือใส่ค่าลงในไฟล์ `.cargo/config.toml` ของโปรเจกต์คุณ:

ในฐานะส่วนหนึ่งของคำสั่ง:

```sh
RUSTFLAGS=--cfg=web_sys_unstable_apis cargo # ...
```

ใน `.cargo/config.toml`:

```toml
[env]
RUSTFLAGS = "--cfg=web_sys_unstable_apis"
```

## การเข้าถึง `HtmlElement` ดิบจาก `view` ของคุณ

สไตล์การเขียนเชิงประกาศ (declarative style) ของเฟรมเวิร์กช่วยให้คุณไม่จำเป็นต้องไปแตะต้องจัดการโหนด DOM โดยตรงเพื่อสร้างหน้าตาอินเทอร์เฟซ ทว่าในบางกรณี คุณอาจต้องการเข้าถึงเอลิเมนต์ DOM ตัวจริงที่อยู่เบื้องหลังการแสดงผลของมุมมอง ในหัวข้อ [“อินพุตแบบไม่ควบคุม”](view/05_forms.html?highlight=NodeRef#อินพุตแบบไมควบคุม-uncontrolled-inputs) เราได้แสดงให้เห็นถึงการทำสิ่งนี้ผ่านชนิดข้อมูล [`NodeRef`](https://docs.rs/leptos/latest/leptos/tachys/reactive_graph/node_ref/struct.NodeRef.html)

เมธอด `NodeRef::get` จะส่งคืนเอลิเมนต์จาก `web-sys` ที่มีชนิดข้อมูลถูกต้องตรงกับชนิดของเอลิเมนต์นั้น ทำให้คุณสามารถนำไปจัดการต่อได้โดยตรง

ลองพิจารณาตัวอย่างต่อไปนี้:

```rust
#[component]
pub fn App() -> impl IntoView {
    let node_ref = NodeRef::<Input>::new();

    Effect::new(move |_| {
        if let Some(node) = node_ref.get() {
            leptos::logging::log!("value = {}", node.value());
        }
    });

    view! {
        <input node_ref=node_ref/>
    }
}
```

ภายในบล็อกของเอฟเฟกต์ด้านบน ตัวแปร `node` จะมีชนิดข้อมูลเป็น `web_sys::HtmlInputElement` ทำให้เราสามารถเรียกใช้งานเมธอดที่เกี่ยวข้องทั้งหมดของมันได้ทันที

(โปรดทราบว่า เมธอด `.get()` จะส่งคืนค่าเป็น `Option` เสมอ เพราะ `NodeRef` จะมีค่าว่างเปล่าอยู่ในตอนแรก จนกว่าโหนด DOM จริงจะถูกสร้างขึ้นในเอกสาร HTML ทั้งนี้ เอฟเฟกต์จะเริ่มทำงานหลังจากคอมโพเนนต์ทำงานไปแล้วหนึ่งทิก (tick) ดังนั้นในกรณีส่วนใหญ่ เอลิเมนต์ `<input>` จึงมักจะถูกสร้างเสร็จเรียบร้อยแล้วเมื่อเอฟเฟกต์เริ่มทำงาน)
