# การดีพลอย

วิธีการนำเว็บแอปพลิเคชันไปดีพลอย (deploy) ใช้งานจริงนั้นมีหลากหลายพอ ๆ กับจำนวนของนักพัฒนา โดยไม่ต้องพูดถึงจำนวนของตัวแอปพลิเคชันเลย ทว่ามีคำแนะนำและเคล็ดลับสำคัญบางประการที่คุณควรตระหนักไว้เสมอเมื่อถึงขั้นตอนการดีพลอยแอปของคุณ

## คำแนะนำทั่วไป

1. **ข้อควรจำ:** จงดีพลอยแอปพลิเคชัน Rust ที่คอมไพล์ในโหมด `--release` เสมอ ห้ามนำเวอร์ชันโหมดดีบัก (debug mode) ไปใช้งานจริงอย่างเด็ดขาด เพราะโหมดนี้ส่งผลกระทบอย่างมหาศาลต่อทั้งประสิทธิภาพความเร็วและขนาดของไฟล์ไบนารี
2. **ทดสอบในเครื่องด้วยโหมด release ก่อนเสมอ:** ตัวเฟรมเวิร์กจะทำการออปติไมซ์บางอย่างเฉพาะในโหมด release ซึ่งไม่ได้เปิดใช้ในโหมดดีบัก ทำให้บางครั้งบั๊กที่ไม่เคยเห็นอาจโผล่ขึ้นมาในจุดนี้ (หากแอปของคุณมีพฤติกรรมเปลี่ยนไปหรือไม่ทำงานอย่างถูกต้องในโหมด release เป็นไปได้สูงว่าอาจเป็นบั๊กในระดับตัวเฟรมเวิร์กเอง และคุณควรเปิด issue บน GitHub พร้อมโค้ดตัวอย่างที่สามารถจำลองปัญหาขึ้นมาใหม่ได้)
3. **ศึกษาบท “การปรับขนาดไบนารี WASM ให้เหมาะสม”:** เพื่อเรียนรู้เทคนิคและแนวทางเพิ่มเติมในการลดขนาดไฟล์ WASM ซึ่งจะช่วยปรับปรุงเมตริกเวลาพร้อมโต้ตอบ (time-to-interactive หรือ TTI) ของแอปพลิเคชันของคุณในการโหลดหน้าเว็บครั้งแรกให้รวดเร็วยิ่งขึ้น

> เราได้รวบรวมตัวอย่างการตั้งค่าสภาพแวดล้อมการดีพลอยจริงจากผู้ใช้งานในชุมชนเพื่อนำมาใช้ประกอบการเขียนบทนี้ โดยเราจะหยิบยกความคิดเห็นบางส่วนมานำเสนอด้านล่าง และคุณสามารถเข้าไปอ่านกระทู้ฉบับเต็มได้ [ที่นี่](https://github.com/leptos-rs/leptos/issues/1152)
