# การทำงานกับ `async`

จนถึงตอนนี้ เราได้ทำงานกับส่วนติดต่อผู้ใช้ (UI) แบบซิงโครนัส (synchronous) เท่านั้น เมื่อคุณป้อนข้อมูลบางอย่าง
แอปพลิเคชันจะประมวลผลทันทีและอัปเดตหน้าจอ ซึ่งเป็นเรื่องที่ดี แต่นั่นเป็นเพียงแค่เศษเสี้ยวเล็ก ๆ
ของสิ่งที่เว็บแอปพลิเคชันทั่วไปทำ โดยเฉพาะอย่างยิ่ง เว็บแอปส่วนใหญ่จำเป็นต้องจัดการกับการโหลดข้อมูลแบบ
อะซิงโครนัส (asynchronous) เช่น การดึงข้อมูลจาก API

ข้อมูลแบบอะซิงโครนัสขึ้นชื่อเรื่องความยากในการผสานเข้ากับส่วนโค้ดแบบซิงโครนัส
อันเนื่องมาจากปัญหาเรื่อง "การแบ่งสีฟังก์ชัน" (function coloring)

ในบทต่อ ๆ ไป เราจะได้เห็นพริมิทีฟเชิงรีแอกทีฟหลายตัวที่ใช้สำหรับจัดการข้อมูลแบบอะซิงก์ แต่สิ่งสำคัญ
ที่ต้องเน้นย้ำไว้ตั้งแต่แรกคือ หากคุณเพียงต้องการรันงานอะซิงโครนัสบางอย่าง Leptos ก็มีฟังก์ชัน
[`spawn_local`](https://docs.rs/leptos/latest/leptos/task/fn.spawn_local.html)
ที่ทำงานข้ามแพลตฟอร์มได้ ซึ่งช่วยให้การรัน `Future` ทำได้อย่างสะดวกง่ายดาย หากพริมิทีฟตัวใด
ที่เราจะพูดถึงในบทนี้ยังไม่ตอบโจทย์ความต้องการของคุณ ลองพิจารณาใช้ `spawn_local`
ร่วมกับการเซ็ตค่าลงในสัญญาณดู

แม้ว่าพริมิทีฟที่เรากำลังจะกล่าวถึงนั้นจะมีประโยชน์อย่างมาก และบางครั้งก็จำเป็นอย่างยิ่ง แต่ก็มีบ่อยครั้ง
ที่ผู้พัฒนาเพียงแค่ต้องการสั่งสปอว์นงาน (spawn a task) ขึ้นมาหนึ่งงานแล้วรอให้มันเสร็จสิ้นก่อนจะทำสิ่งอื่นต่อไป
ในกรณีเช่นนั้น ให้ใช้ `spawn_local` ได้เลย!
